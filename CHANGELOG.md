# Changelog

All notable changes to OpenTodo are documented here. The format follows [Keep a Changelog](https://keepachangelog.com/en/1.1.0/).

## [Unreleased]

### Added
- Passkeys (OpenSpec change `passkeys`): when `OPENTODO_BASE_URL` is https (or a localhost dev origin), users register several named passkeys in **Settings → Security** and sign in without a password, either with "Sign in with a passkey" or through browser autofill on the email field. The password stays as a fallback. Passkeys can be renamed and revoked. A signature counter that goes backwards refuses the sign-in and flags the passkey as suspicious. New routes: `/api/v1/passkeys` (register options/finish, list, rename, delete; authenticated) and `/api/v1/auth/passkey` (options, finish; anonymous, rate limited like login). `auth/status` gains `passkeysAvailable`. New `passkeys` table (migration `0003`). The verification code lives in `internal/webauthn`, with one new dependency, `github.com/fxamacker/cbor/v2` (plus its transitive `x448/float16`). Server binary grows from 11,444,386 to 11,751,586 bytes (+0.29 MiB). No new npm dependency and no new environment variable.
- Subtask trees (OpenSpec change `subtask-trees`): tasks nest to any depth through the existing `parent_id`; Project and Inbox views render the tree with per-device collapse, date views list subtasks flat with a parent breadcrumb; parents show `completed/total` progress over direct subtasks; completing a parent completes its open descendants and deleting one tombstones the subtree (reopen does not cascade); completing the last open subtask offers to complete the parent; `a` adds a subtask, Tab / Shift+Tab re-parent from the keyboard, and the detail panel has a subtask list and a parent picker; concurrent re-parenting converges with a deterministic, write-free cycle-breaking rule shared by every device; `POST`/`PATCH /api/v1/tasks` reject a parent that is missing, deleted, in another project or would form a cycle.
- Command-line client `ot` (OpenSpec change `cli-client`): a stdlib-only static binary built from `cmd/ot` that talks to any server over the REST API with a bearer token. `ot login` mints a `cli@<hostname>` token from email and password; profiles live in the user config directory with owner-only permissions and are overridden by `OPENTODO_URL` / `OPENTODO_TOKEN` / `--profile`. Commands: `list` with the web's view filters (aliases `today`, `inbox`, `upcoming`), `add`, `edit`, `done`, `reopen`, `rm` with id-prefix references, `project …`, `token …`, `export`, `auth …`. `--json` prints the API's own shapes; exit codes 0/1/2/3/4. Built by `make cli` and cross-compiled for linux/darwin/windows × amd64/arm64 in CI; not included in the container image. Docs in `docs/cli.md`.
- OpenSpec changes drafted for every roadmap item (35 changes, 33 new capabilities plus deltas to existing ones), all passing strict validation. Nothing is implemented yet; each is a planning artifact for `/opsx:apply`.
- Walking skeleton (OpenSpec change `bootstrap-core-platform`): Go + SQLite server with embedded React PWA, local-first storage, field-level conflict-free sync, owner setup and sessions, API tokens, REST API with write-through to the op log, JSON export, single distroless container, Coolify-ready compose file, CI pipeline.
