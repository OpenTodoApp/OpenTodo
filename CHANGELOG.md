# Changelog

All notable changes to OpenTodo are documented here. The format follows [Keep a Changelog](https://keepachangelog.com/en/1.1.0/).

## [Unreleased]

### Added
- Task assignment (OpenSpec change `task-assignment`): additive task field `assignee_id` (account id or null) synced by last-writer-wins. The server checks a non-null assignment at receipt: a current member of the task's shared project, or the author for a personal task; anything else is refused per op with the new reason `not_a_member` plus the server's value (REST: `400 not_a_member`); viewers get `forbidden`. When a member leaves or is removed, the server writes `assignee_id: null` ops (device `server`) for their tasks in that project in the same transaction, so every device converges without client logic. A new `internal/notify` package defines a post-commit `Sink` interface (`sync.Service.AddSink`) for later push and webhook delivery; the in-app sink stores a notification when someone assigns a task to someone else, served by `GET /api/v1/notifications` and `POST /api/v1/notifications/{id}/read` (authenticated, 404 for other accounts' rows); read notifications older than 90 days are swept at start-up. Web app: assignee picker in the detail panel and `Shift+A` (members from the local membership cache, "Unassigned", type to filter), assignee chip on rows in shared projects, **Assigned to me** view grouped by project (`g a`, sidebar count, offline), notification bell with unread badge that opens the task and marks it read (cached locally, reads confirmed when online), a cross-scope copy drops an assignee who is not a member of the destination, and a refused assignment shows the task unassigned with a notice. Migration `0011_task_assignment.sql` (idempotent) adds `notifications`; Dexie version 6 indexes `tasks.assignee_id` and adds a `notifications` table. No new dependency or environment variable; client bundle +2.6 KB gzipped (JS +2.5, CSS +0.1).
- Project sharing (OpenSpec change `project-sharing`): a project owner shares a project with other accounts on the same server by exact email as `viewer`, `editor` or `admin`; every project keeps exactly one `owner`. The op log becomes per scope: every op and materialized field belongs to `user:<id>` (Inbox, unshared projects, labels, saved views) or `project:<id>` (a shared project and its tasks), and `Pull` serves the caller's scopes with the same single cursor (`seq` is global), so the sync request is unchanged. Each op is authorized against the author's membership when the server receives it (viewer: nothing; editor: tasks; admin: tasks and project fields except `deleted_at`; owner: everything); refused ops are reported individually in a 200 response (`rejected: [{id, reason}]`, reasons `forbidden` and `scope_change`) together with the server's current op for each refused field, never stored and never blocking the outbox. A newly added member's devices replay the project's history behind their cursor first (paged, `hasMore`, tracked per device), and every response lists the caller's `memberships`, from which devices purge projects they left or were removed from. A task never changes scope: moving it to a project shared differently is a copy plus a tombstone, and deleting a shared project (owner only) tombstones it and its tasks and copies open tasks into the owner's Inbox. First share relabels the project's existing ops without rewriting them, so the owner's devices keep their cursor. New routes `GET/POST /api/v1/projects/{id}/members`, `PATCH/DELETE /api/v1/projects/{id}/members/{userId}` (`me` to leave) and `POST /api/v1/projects/{id}/transfer` (all authenticated; non-members get 404; errors `user_not_found`, `owner_must_transfer`, `already_member`, `forbidden`); REST collections and the export include shared projects with read-only `role` and `owner_id`; REST writes answer `403 forbidden` or `400 scope_change`. Membership changes are recorded as `role.changed` audit events (`none` → `project.editor`, ...); webhooks fire for every member of a shared project; live wake-ups reach every member, and a membership change wakes devices with a cursor-less event. Web app: shared badge in the sidebar, members and roles in the project header, a share dialog (`Shift+S`) to add, re-role, remove, leave and transfer, read-only rendering for viewers from the cached membership (offline too), and a notice naming the project and tasks when changes were refused. Migration `0008_project_sharing.sql` adds `op_scopes`, `scope_fields` (replacing `fields`), `project_scopes`, `project_members` and `member_backfills`, backfilling `user:<id>` for existing rows (idempotent); Dexie version 5 adds a `memberships` table. Older clients keep syncing their personal data unchanged. No new dependency or configuration; server binary +0.13 MB (stripped), client bundle +3.6 KB gzipped.
- Scheduled backups (OpenSpec change `backups`): the owner configures backups in **Settings → Backups** or through owner-only routes `GET/PUT /api/v1/backups/settings`, `GET /api/v1/backups`, `POST /api/v1/backups/run` and `POST /api/v1/backups/test`. A run snapshots the database with `VACUUM INTO` while the server keeps running and writes `opentodo-<time>-<generation>.tar[.gz][.enc]` (a `manifest.json` with version, schema, checksum and encryption flag, plus the database) to a folder (default `<data>/backups`), an S3-compatible bucket (SigV4 over `net/http`, path-style option) or a WebDAV collection. Hourly, daily or weekly schedules in the server's time zone, a missed run executes once at startup, keep-last-N plus optional max-age retention that never deletes the newest archive, run history for 90 days, a destination test, and optional encryption (argon2id + AES-256-GCM in 1 MiB chunks, format `OTBK1` documented byte for byte). Destination credentials and the passphrase live only in `<data>/secrets/backup.json` (0600), are never returned or logged and never archived. `opentodo restore [--passphrase-file f] <archive>` verifies, decrypts, refuses newer schemas and running servers (new data-directory lock `opentodo.lock`), keeps `opentodo.db.pre-restore-<time>` and sets a new log generation; `/api/v1/sync` responses gain an additive `generation` field and devices that see it change re-send their local fields with their original clocks, so edits made after the backup survive and conflicts resolve by timestamp. Optional `OPENTODO_BACKUP_*` presets. Migration `0007_backups.sql` adds `backup_runs` and the log generation (and the shared `settings` table if it does not exist yet). Runs and restores are recorded in the audit log as `backup.created` / `backup.restored`. No new dependency; server binary +0.6 MB (stripped), client bundle +4.4 KB gzipped. See `docs/backups.md`.
- Time blocking (OpenSpec change `time-blocking`): **Day** and **Week** calendar views (`g d`, `g w`, sidebar, `/day[/YYYY-MM-DD]`, `/week[/YYYY-MM-DD]`) rendered from local data with a 15-minute grid. A task with a due time is a block at that time sized by `estimate_minutes` (unestimated: 30 minutes, dashed, no label); date-only tasks sit in each day's unscheduled lane; overlapping blocks are laid out side by side with an overlap marker, capped at four columns with a "+N" list; each day header shows planned estimates against a day length and is marked over capacity; a current-time line marks today. Placement uses native pointer events (no library): drag from the lane, from a "Plan from a list" panel (Inbox, no date, overdue or a project) or an existing block onto a slot to set the due date and time, drop on the lane to clear the time, drag a block's lower edge to set the estimate in 15-minute steps; touch lifts after a long press. Keyboard parity: `j`/`k` select, arrows move by 15 minutes or a day, Shift+Up/Down change the estimate by 15 minutes, `u` unschedules, Enter opens the task, `[`/`]`/`t` change the range; `s` on a list task opens the Day view in placement mode (arrows, Enter places, Esc cancels). The detail panel has an estimate control (shorthand `15m`, `1h`, `1h30`, `90`, presets 15–120 minutes, clear) and `e` on a selected row focuses it; rows show estimates as `1h 30m`. Duration filter chips (Quick wins ≤ 15 min, Under 30 min, Over 1 h, Unestimated) in Inbox, Today, Upcoming and project views, remembered per view and device; the shared `durationPredicate` (`web/src/lib/filters.ts`) is ready for the filter language. Grid start and end hour and day length (defaults 06:00–22:00, 8 h) are per-device settings in **Settings → Calendar**, stored in local `meta` and never synced. Every placement is an ordinary `due` or `estimate_minutes` edit through the op log, so it works offline and converges by last-writer-wins. Reuses the `estimate_minutes` field added by `nlp-quick-add`: no schema, API or op-format change, no new dependency or environment variable; client bundle +6.0 KB gzipped (JS +5.6, CSS +0.4).
- Recurring tasks (OpenSpec change `recurring-tasks`): additive task fields `recurrence` (a human-readable rule such as `every last weekday` or `every 3 days after completion`, optionally `until YYYY-MM-DD` or `for N times`; max 200 characters, validated by the server, stored in canonical lowercase form) and `series_id`. One grammar and next-occurrence calculator is implemented in Go (`internal/recurrence`) and TypeScript (`web/src/lib/recurrence.ts`) and both run the same 180 shared vectors (`web/src/lib/recurrence.vectors.json`: month-end clamping, leap days, last weekday, ordinal weekdays, catch-up, completion-relative, end conditions, DST-free floating dates). Completing a recurring task writes, in one batch, a completed occurrence record whose id is derived from the series id and occurrence date (SHA-256 name-based UUID, `ids.NameID` / `web/src/lib/ids.ts`) and moves the series' `due` to the next occurrence, so two devices completing the same occurrence offline converge to one Completed entry and one next date; the end condition completes the series normally, and `for N times` is counted from the records. Skip (`Shift+S`) and "This occurrence only" (`Shift+O`) in the detail panel, which also gains a rule field with suggestions, validation and a live preview of the next three dates; rows show a ↻ indicator. `PATCH /api/v1/tasks/{id}` with `completed_at` on a recurring task runs the same flow server-side. Grammar reference in `docs/recurrence.md`. No new dependency or environment variable; client bundle +5.9 KB gzipped. **Mixed versions**: update the server before clients (an older server rejects sync batches carrying the new fields until upgraded; the ops wait in the outbox). An older client completing a recurring task records a plain completion of the whole series; reopen it on an updated device to continue the schedule.
- Share capture (OpenSpec change `share-capture`): the PWA manifest declares a GET Web Share Target, so the installed app appears in the phone and desktop share sheet, and a capture screen at `/share` prefills a quick-add title (page title, or the link's host), a description (shared text followed by the link) and a project picker (Inbox by default); Enter saves through the normal op path, Esc cancels, a popup closes itself afterwards. It opens from the precached shell with no network, and on a signed-out device keeps the shared page in memory through sign-in (never in storage or on the server). **Settings → Capture** offers a bookmarklet generated for the server's own origin (no token) that opens the capture screen in a popup with the page's URL, title and selection. A Manifest V3 browser extension for Chromium and Firefox in `extension/` (toolbar button, "Add to OpenTodo" context menu, Alt+Shift+O; permissions `activeTab`, `contextMenus`, `scripting`, `storage`; no host permissions, no token, no network requests) is packaged by `make extension` and CI as `opentodo-browser-extension.zip`. Payload limits: title 500 characters, text 16 KB with a truncation note, `http(s)` links only. No server change, no new dependency; client bundle +2.1 KB gzipped. Guide in `docs/capture.md`.
- Audit log (OpenSpec change `audit-log`): the server records sign-in success and failure (with a reason; one `rate_limited` event per address and window under brute force), sign-out, API token creation and revocation, invitation creation, acceptance and revocation, audit settings and webhook policy changes, data exports and audit exports in a new `audit_events` table (migration `0005_audit_log.sql`, plus the shared `settings` table if absent). Credential changes are written in the same transaction as their event. Details are allow-listed in `internal/audit` (typed constructors, a test checks them against entity fields and secret names), so task content, passwords, token secrets and codes never reach the log. Client address logging is off by default and disabling it erases stored addresses; user agents are truncated to 200 bytes; retention is 90 days by default (7–3650), pruned at startup, hourly and when lowered. Owner routes `GET /api/v1/audit` (filters, cursor, `limit` ≤ 200), `GET /api/v1/audit/export` (NDJSON), `GET/PUT /api/v1/settings/audit`; `GET /api/v1/me/activity` for every user. **Settings → Audit log** (owner) and **Settings → Security → Recent activity** (everyone), both live-only with an offline notice. Passkey registration, removal and sign-in (success and failure, with reasons) are recorded too. Constructors for MFA, OIDC, role and backup events are ready for those changes. No new dependency or configuration; bundle +3.5 KB gzipped.
- Passkeys (OpenSpec change `passkeys`): when `OPENTODO_BASE_URL` is https (or a localhost dev origin), users register several named passkeys in **Settings → Security** and sign in without a password, either with "Sign in with a passkey" or through browser autofill on the email field. The password stays as a fallback. Passkeys can be renamed and revoked. A signature counter that goes backwards refuses the sign-in and flags the passkey as suspicious. New routes: `/api/v1/passkeys` (register options/finish, list, rename, delete; authenticated) and `/api/v1/auth/passkey` (options, finish; anonymous and rate limited per address: a sign-in attempt shares the login window, challenge requests have their own). `auth/status` gains `passkeysAvailable`. New `passkeys` table (migration `0004`). The verification code lives in `internal/webauthn`, with one new dependency, `github.com/fxamacker/cbor/v2` (plus its transitive `x448/float16`). Server binary grows from 11,444,386 to 11,751,586 bytes (+0.29 MiB). No new npm dependency and no new environment variable.
- Data import (OpenSpec change `data-import`): **Settings → Import data** (`g` then `Shift+I`) and `POST /api/v1/import/preview`, `POST /api/v1/import`, `GET /api/v1/import/jobs[/{id}]`, `POST /api/v1/import/jobs/{id}/undo`. Accepts the app's own export (exact round trip with ids, labels, sub-projects, subtasks and tombstones), CSV with documented columns, and three structurally detected JSON shapes from other task managers. A dry-run preview lists per-row outcomes (create, update, skip with reason, error with row number) and warnings for dropped attributes (recurrence, reminders, attachments, comments); duplicates are detected by id, by source rows remembered from earlier imports and by a title/project/due fingerprint. Jobs run in the background, write only through the op log (device `import`, batches of 1,000 ops), one per account at a time, and can be undone as a whole. Optional `OPENTODO_IMPORT_MAX_MB` (default 20); 50,000 rows per file. Migration `*_data_import.sql` adds `import_jobs` and `import_items`. No new dependencies; binary +0.7 MB (embedded time zone database), client bundle +3.8 KB gzipped. Docs in `docs/import.md`.
- Outbound webhooks (OpenSpec change `webhooks`): per-account webhooks in **Settings → Webhooks** and `/api/v1/webhooks*` for `task.created|updated|completed|reopened|deleted` and `project.created|updated|archived|deleted`, optionally limited to one project. Events are derived from the winning changes of each committed op batch (device sync, REST, CLI), one per entity per batch, never from losing or duplicate ops. Versioned JSON payload with the current entity and `changes: {field: {from, to}}`, signed `X-OpenTodo-Signature: v1=HMAC-SHA256(secret, "<timestamp>.<body>")` with a `whsec_` secret shown once. Durable SQLite queue with one worker, 10 s timeout, six retries over about 27 h with jitter, auto-disable after 20 consecutive failures, delivery log (last 100, 30 days) with test ping and redeliver. SSRF protection: resolve-then-pin dialer refusing loopback, private, link-local/metadata, CGNAT, ULA, multicast and IPv4-mapped targets, no redirects, no environment proxy; the owner can allow private network targets in Settings (optional preset `OPENTODO_WEBHOOKS_ALLOW_PRIVATE`). Migration `0003_webhooks.sql` (tables `webhooks`, `webhook_deliveries`, shared `settings`). Docs in `docs/webhooks.md`.
- Natural-language quick add (OpenSpec change `nlp-quick-add`): the quick-add line understands due dates and times ("tomorrow", "next Wed at 3pm", "in 3 days", "3 Feb", "12/11", "16:30"), `#project` (sub-projects included; equal names resolve to the shallowest), `@label` (matched ignoring case, created on Enter if new, stored as label ids), `p1`–`p4` and estimates (`+30m`, `+1h30`) in English, German, French, Italian, Spanish and Portuguese, entirely offline and deterministically. Recognised tokens show as chips under the input with a title preview; dismiss a chip (click `×`, or Backspace twice at the end of the line) or "quote" text to keep it literal. Explicit tokens override the view's defaults. Settings → Quick add turns parsing off, picks languages and the day/month order, per device. Syntax reference in `docs/quick-add.md`.
- Additive task field `estimate_minutes` (integer 1–10080 or null): validated by the server, synced, accepted by `POST`/`PATCH /api/v1/tasks`, included in the export and shown as a chip on the task row. **Update the server before clients**: an older server rejects sync batches that contain the new field until it is upgraded (the ops wait in the outbox, nothing is lost).
- Saved views and dashboards (OpenSpec change `custom-views`): a synced `view` entity (name, query string, kind `list` or `dashboard`, `group_by`, `sort_by`, `sort_dir`, pinned, position, colour, panels, soft delete). Save the current query from the Filter view with `s` or **Save view**; a saved view shows its query in an editable input (`/`, Enter saves, Esc discards), grouping by project, due date, priority, label or none and sort by due date (undated last), priority, manual order, created or title, ascending or descending, from keyboard-reachable menus; a query that no longer parses shows the error and no results. Pinned views are listed under **Views** in the sidebar with live open counts computed in one pass, with rename, reorder, unpin, delete and "set as start view" in their menu; `g v` opens the overview. Dashboards show up to six saved views as panels (count and first ten tasks, live), with add, arrange and remove, Tab / Shift+Tab between panels and a "View removed" placeholder. The start view is a per-device preference in local `meta` (not synced) with an Inbox fallback and notice. Unknown option values received by sync are shown as defaults without being rewritten. REST `/api/v1/views` validates names, enumerations, immutable `kind`, panel ids and the query with a Go port of the filter parser (`internal/filter`, tested against `docs/filters.md` like the TypeScript one); the export gains `views`. Dexie database version 4 adds a `views` table. No new dependencies; client bundle +7.8 KB gzipped (JS +7.5, CSS +0.3).
- Filter queries (OpenSpec change `filter-query-language`): a **Filter** view (`g f`, or the sidebar) with a one-line query language: `@label`, `#project` and `##project` (with sub-projects), `p1`–`p4`, `due` / `created` compared with `< <= = >= > before after` against `today`, `tomorrow`, `yesterday`, weekday names, ISO dates or `N days [ago]`, keywords `overdue`, `today`, `tomorrow`, `no date`, `no time`, `no project`, `no labels`, `subtask`, `completed`, `open`, and `search:` over title and notes, combined with `&`, `|`, `!` and parentheses. Evaluated entirely on the device from local data (offline, live as synced changes arrive, no new API). Syntax errors name the position and what was expected and keep the previous results; unknown label or project names warn and match nothing. Results are grouped by project; Enter jumps to the first result, Esc returns to the input, Up / Down recall the last 20 queries kept per device and never synced. Grammar and examples in `docs/filters.md`. No new dependencies; client bundle +4.6 KB gzipped.
- Labels (OpenSpec change `labels`): a synced `label` entity (name, colour, position, soft delete) referenced by id from `task.labels`, so renaming is one operation and never rewrites tasks. Assign from the task detail panel or with `L` on a selected task (type-ahead, create on Enter, multi-select); chips on task rows; a collapsible Labels group in the sidebar with live open counts and a per-label view grouped by project (`g l` opens the overview); rename, recolour, reorder, delete (removes the id from every task) and merge of duplicates created concurrently on other devices. REST `/api/v1/labels` collection, task `labels` validated against existing labels, export gains `labels`; `ot add/edit --label` accepts a label name (case-insensitive) or id and creates missing labels. The whole-array convergence caveat of `task.labels` is documented in `docs/sync.md`. Client bundle +4.3 KB gzipped, no new dependencies.
- Nested projects (OpenSpec change `project-hierarchy`): projects nest to any depth through the existing `parent_id`, with no schema or op-format change. The sidebar renders a collapsible tree (indentation capped after level 3, Left / Right on a focused row, collapse state stored per device in the local `meta` table and never synced, ancestors expand when you navigate to a sub-project); a collapsed parent's count includes its whole subtree. "Move to" in the project menu (keyboard: `m`) excludes the project, its descendants and archived projects and places the project last among its new siblings; the create form takes an optional parent that defaults to the current project; a project view ends with a "Sub-projects" list with rolled-up counts. Archiving cascades one op per descendant (unarchive does not); deleting moves direct sub-projects to the deleted project's parent and open tasks to the Inbox. Concurrent moves that form a cycle are broken identically on every device by the same write-free rule as subtasks; `POST`/`PATCH /api/v1/projects` reject a parent that is missing, deleted or would form a cycle (`400 invalid_input`). Bundle +1.7 KB gzipped.
- Subtask trees (OpenSpec change `subtask-trees`): tasks nest to any depth through the existing `parent_id`; Project and Inbox views render the tree with per-device collapse, date views list subtasks flat with a parent breadcrumb; parents show `completed/total` progress over direct subtasks; completing a parent completes its open descendants and deleting one tombstones the subtree (reopen does not cascade); completing the last open subtask offers to complete the parent; `a` adds a subtask, Tab / Shift+Tab re-parent from the keyboard, and the detail panel has a subtask list and a parent picker; concurrent re-parenting converges with a deterministic, write-free cycle-breaking rule shared by every device; `POST`/`PATCH /api/v1/tasks` reject a parent that is missing, deleted, in another project or would form a cycle.
- Command-line client `ot` (OpenSpec change `cli-client`): a stdlib-only static binary built from `cmd/ot` that talks to any server over the REST API with a bearer token. `ot login` mints a `cli@<hostname>` token from email and password; profiles live in the user config directory with owner-only permissions and are overridden by `OPENTODO_URL` / `OPENTODO_TOKEN` / `--profile`. Commands: `list` with the web's view filters (aliases `today`, `inbox`, `upcoming`), `add`, `edit`, `done`, `reopen`, `rm` with id-prefix references, `project …`, `token …`, `export`, `auth …`. `--json` prints the API's own shapes; exit codes 0/1/2/3/4. Built by `make cli` and cross-compiled for linux/darwin/windows × amd64/arm64 in CI; not included in the container image. Docs in `docs/cli.md`.
- Invitations (OpenSpec change `invitations`): the owner creates single-use, expiring invitation links in **Settings → Members**, optionally bound to an email, lists them with status (pending, accepted, expired, revoked) and revokes pending ones. Invitees accept at `/invite/<token>` while sign-up stays closed. New routes `GET/POST /api/v1/invitations`, `DELETE /api/v1/invitations/{id}`, public `GET /api/v1/invitations/{token}`, and an optional `invitation` field on `POST /api/v1/auth/register`. Migration `0002_invitations.sql`.
- Live push of changes between devices (OpenSpec change `realtime-sync-channel`): an authenticated server-sent event stream at `GET /api/v1/sync/events` wakes a user's other devices as soon as operations are recorded by another device or through the REST API. The wake-up carries only the latest cursor; data still flows through the sync exchange. The web app reconnects with backoff, syncs on every reconnect, relaxes polling to 5 minutes while connected and falls back to 30 s polling otherwise; the status pill shows **Live** or **Polling**. No new dependency or configuration; see `docs/sync.md` and the proxy notes in `docs/self-hosting/`.
- OpenSpec changes drafted for every roadmap item (35 changes, 33 new capabilities plus deltas to existing ones), all passing strict validation. Nothing is implemented yet; each is a planning artifact for `/opsx:apply`.
- Walking skeleton (OpenSpec change `bootstrap-core-platform`): Go + SQLite server with embedded React PWA, local-first storage, field-level conflict-free sync, owner setup and sessions, API tokens, REST API with write-through to the op log, JSON export, single distroless container, Coolify-ready compose file, CI pipeline.
