# Design

## Context

See proposal.md for motivation. Relevant current state:

- The row is one memoised component, `web/src/app/TaskRow.tsx` (about 420 lines; the board card is the same component with `card`), fed by `task-list/ListRow.tsx` from `rowRenderer` in `task-list/ListGroups.tsx`, and directly by `FilterView`, `SavedViewView`, `DashboardView`, `method/MethodListView`, `review/ReviewView`, `review/CloseDay`, `review/DailyCheck`, `review/MonthlyLook`, `display/DisplayColumn`, `ProjectsView` and `Sidebar` (favourites). Plan and the calendar's day lists draw their own `calendar/PlanRow.tsx` with the same tone rules copied by hand.
- `calm-rows` (open, archiving within the hour) added the Calm/Detailed split: `useRowDetail()` reads the synced `user_prefs.row_detail`, `TaskRow` takes `detail`, `implied` and `omitLabel`, `rowCounts()` feeds the quiet trailing group `RowCounts`, labels render as `LabelDots`, and `budget.test.tsx` pins `MAX_CALM_ROW_ITEMS = 4`. `time-tracking` folds the tracked figure into the estimate item; `ux-feedback-2` defines the quiet hover ("no newly shown control") and the 2 px selected bar; `lean-chrome` fixes the empty views. All four touch `task-list-presentation`.
- Row metadata comes from three primitives in `web/src/ui/Chips.tsx`: `ToneText`, `NeutralChip` (pill), `LabelChip` (pill with the stored colour), plus `LabelDots`. Icons are 12 px in chips, 16 px in rows (design-system "Secondary text is one size").
- Keyboard: `s` opens the Do on popover, `1` to `4` set priority, `.` (also `Shift+F10` and the Menu key) opens the row menu; `j`/`k` move real focus between the rows' open controls (task-list-presentation "Lists for assistive technology"); `Tab` indents a subtask only while the quick add is not focused (`list.indent`).
- Constraints: tokens only (`src/ui/tokens/lint.test.ts`), every foreground and background pair in `pairs.ts`, no `aria-label` on a role-less span, 44 px targets on coarse pointers, a cursor move re-renders two rows (`listPerformance.test.tsx`), stories with light/dark × 375/1280 baselines, five translation catalogs, and the interface budget (design-system "Interface budget").

**Post-archive text.** This change writes its deltas against the requirement text that `calm-rows`, `time-tracking`, `ux-feedback-2` and `lean-chrome` leave in `task-list-presentation`, `appearance-preferences` and `sections-and-boards` once archived (the other session is archiving them now), the way `task-locations` D10 did. "One row anatomy", "Metadata language", "Selected row indicator", "Row detail preference" and "Appearance in Settings" are MODIFIED with their full post-archive text folded in; "Row detail in lists" is REMOVED; the time column, the revealed actions and the shared row are ADDED so they cannot collide. Task 7.1 re-reads those requirements at apply time and reconciles wording if an archive changed a sentence.

## Goals / Non-Goals

**Goals:**
- One row component, one language, three shapes (row, card, compact); every caller keeps working by deleting a prop, not adding one.
- The time column is a per-list fact computed once where the groups are built, so 2,000 rows read one value and the column never flickers row by row.
- Revealed actions that are real, keyboard-reachable buttons, never hover-only, never on touch, and never a layout shift.
- The pills go: the only chip left in a row is the label chip.

**Non-Goals:**
- No change to the panel's facet chips, the sidebar rows, the group headers, the page title, the empty views or the display routes' large rows.
- No new token (the muted and faint steps come from `tokens-v2` when it lands; until then the current `text-muted` and `text-faint`), no new icon, no new shortcut.
- No swipe actions, no completion animation, no list reflow (other changes).

## Decisions

**D1. Calm is the only row; `row_detail` is retired, not removed.** `useRowDetail()`, the `detail` prop, `PRIORITY_RING` (the all-coloured table), `DUE_TONE` and the Detailed branches of `TaskRow` are deleted; `PRIORITY_RING_CALM` and `dueToneCalm` become the only tables. `row_detail` stays in `internal/sync/ops.go` `Schema`, `types.ts` and `USER_PREFS_DEFAULTS` (op fields are never removed); `readAppearance` stops reading it and `setAppearance` stops accepting it; the Appearance "Rows" `SettingRow` and its settings-index entry go. Alternative: keep Detailed as a hidden preference for people who liked it. Rejected: two languages means every later row change is designed and baselined twice, which is how the pills survived `ux-overhaul`. Users who want more on a row have the panel one click away and the custom field columns in the wide layout.

**D2. The time column is a list-level fact.** `useListModel` (and the direct callers' list builders) compute `timeColumn: { show: boolean }` once per render from the visible rows: true when any row has a due time or (no due time and a deadline). It flows down through `rowRenderer` and `ListRow` as one boolean prop, so a row re-renders only when the fact flips, not per row. The width is one CSS custom property on the list root, `--row-time-w`, set from the user's time format: `3.25rem` for 24-hour, `4.75rem` for 12-hour (fits "12:00 PM" at the metadata size with tabular figures), computed in `useDateTimeFormat` and applied by `TaskListView` and every direct caller through a shared `rowTimeWidth(format)` helper. The column is a `span` with `data-row-time` and `w-(--row-time-w)`, between the checkbox slot and the open button, holding `ToneText` with the time or the countdown. Alternatives: (a) always render the column: untimed lists (most projects) would push every title 52 px right for nothing; (b) per-row column only when that row has a time: titles would zigzag within a list. Rejected both.

**D3. What the column holds.** `describeDue().time` (added by calm-rows) when present, in the date tone (`dueToneCalm`), else `describeDeadline()` when the task has a deadline and no due time, in `DEADLINE_TONE`, else nothing. A zone-fixed due shows the viewer's local time in the column; the "fixed to Zone" hint stays in the line in the faint colour. The line never repeats what the column holds: `calmDateText` already drops the time when `implied.date`; the deadline item in the line is rendered only when the column did not take it. Board cards (`card`) and compact rows have no column; the same value leads their line.

**D4. The metadata line is one run of `ToneText`.** Every item that was a `NeutralChip` (estimate, blocked, streak, field values, "+n", breadcrumb) becomes `ToneText tone="muted"` with its icon where it had one; the line's container gets `data-row-meta` and a CSS rule that draws a middle dot between adjacent items (`[data-row-meta] > * + *::before { content: "·" }` in the faint colour, `aria-hidden` by construction since it is generated content, so screen readers hear the items in order without the dots). `NeutralChip` is no longer imported by `TaskRow`; it stays in `Chips.tsx` for the panel and settings. The origin keeps `OriginChip` but renders in the quiet (text) style always. Alternative: keep the estimate as a pill because "1h" alone is ambiguous. Rejected: the spoken label stays "Estimate 1 h" and the position in the run is fixed, and Things and Todoist show bare durations without complaint.

**D5. Labels are the only chips, with the dot inside.** `LabelChip` gains the colour dot before the name (6 px, the stored colour, as `LabelDots` draws it) and a smaller variant for rows. `TaskRow` renders at most two `LabelChip`s then a `+n` text item carrying the full list as `ReadAs` and a `Tooltip`, wrapped in a `role="group"` named "Labels" (the `LabelDots` group semantics kept). `LabelDots` itself is removed if nothing else uses it (task 2.5 checks). Alternative: keep dots-only as calm-rows chose. Rejected: a dot without a name is a colour test, and the October review found dots-only rows read as "something is tagged" without saying what; two named chips cost one line of width and are what Todoist and TickTick settled on.

**D6. The project lives in the trailing group.** `showProject && project` renders `<span data-project className="truncate max-w-48 text-muted">` as the first item of the trailing group (before the counts and the origin) from 640 px, and as the last item of the metadata line below 640 px (`hidden sm:inline` / `sm:hidden` pairs, one element each so the DOM has one project per row at a time through a `useMediaQuery('(min-width: 640px)')` shared hook, not CSS duplication, so assistive technology hears it once). "Inbox" as a project word goes: the Inbox view never shows it and other views show no project for a project-less task (the omission table). Alternative: keep the project as a pill at the line's end. Rejected: it is the loudest item on every row in Today and Upcoming and says the least.

**D7. Revealed actions overlay the trailing group.** The `li` keeps `group`; a `span data-row-actions` is absolutely positioned at the row's right edge (`right-2 top-1/2 -translate-y-1/2`), hidden with `opacity-0 pointer-events-none` and shown with `group-hover:` and `group-focus-within:` (both `opacity-100 pointer-events-auto`), while the trailing group gets `group-hover:opacity-0 group-focus-within:opacity-0` so the two never overlap visibly. The trailing group keeps its place in the DOM and is never `aria-hidden`, so screen readers always hear the counts. The actions render only when `useMediaQuery('(min-width: 768px) and (pointer: fine)')` is true and the row is not `readOnly` and not `card` and not `inline`. Three `Button variant="ghost" size="sm" icon` (28 px visual, 8 px gap: WCAG 2.2 2.5.8 satisfied without the 44 px coarse rule, which does not apply on fine pointers), each with `Tooltip` "Schedule · s", "Priority · 1 to 4", "More · ." (keys from the registry entries `list.schedule`, `list.priority`, `list.actions`, never typed by hand). They call the same handlers the shortcuts call (`useListShortcuts` exposes `openSchedule(id)`, `openPriority(id)`, `openMenu(id)` through `RowContext`), anchored to the button. Keyboard: the buttons have `tabIndex={0}` so Tab from the open control reaches them; `useListBindings`'s `j`/`k` keep focusing `[data-row-open]` only; `Esc` from an action returns focus to the open control. Focus-not-obscured: the list scroller's `scroll-padding-bottom` is the toast's height plus the selection bar's height, and `focus()` on an action calls `scrollIntoView({ block: 'nearest' })`, so the sticky header, the bar and the toast never cover a focused action (WCAG 2.2 2.4.11); `budget.test.tsx` asserts the padding. Alternatives: (a) actions in the DOM only on hover: hover-only controls fail the keyboard rule and jump for screen readers; (b) always-visible icon buttons like Todoist's: six grey icons per row is the noise this change removes; (c) a right-click menu only: exists already (`.`), and discoverability of the three most common edits was the point. The `ux-feedback-2` sentence "no newly shown control" on hover is superseded by this change's MODIFIED "Selected row indicator".

**D8. Plan and the calendar's day lists use the compact shape.** `TaskRow` gains `shape: 'row' | 'card' | 'compact'` (`card` becomes `shape="card"`; `TaskCard` stays as a wrapper). `compact` renders the checkbox, the time (leading, not a column: Plan columns are 1/7 of the frame), the title and the estimate, and nothing else, which is what `PlanRow` draws by hand today; `PlanRow` becomes a thin wrapper that adds the projection dimming and the event rows, so the tone tables exist once. Alternative: leave `PlanRow` alone. Rejected: it is the one place the row language is copied, and it drifted once already (its own "P1" text treatment).

**D9. Review and Close the day rows are plain `TaskRow`s.** They already are; the change only verifies that their stories show the column and the chips and that Close the day's decision controls sit after the row without colliding with the revealed actions (Close the day rows pass `readOnly`-like `actions={false}` so the decision buttons are the only controls: a new boolean prop `actions`, default true).

**D10. Interface budget.** Rows of chrome above the first item: unchanged (header, quick add). Task properties visible by default: at most seven on a row: the time column, the date words, the deadline or start, the estimate, the labels group, the project and the counts group; `budget.test.tsx` replaces `MAX_CALM_ROW_ITEMS = 4` with `MAX_ROW_META_ITEMS = 5` for the line (date words, deadline/start, estimate, labels group, and one of blocked/streak/fields/origin) and asserts the column and the trailing group separately, on the seeded Today row with a time, an estimate, a project, three labels, subtasks and comments. Sidebar destinations, scroll regions and shortcuts: unchanged; the three actions reuse registered keys and add none.

**D11. Stories and baselines.** `taskRow.stories.tsx`: `TimeColumn` (24-hour and 12-hour lists), `ActionsRevealed` (a story prop `forceActions` that sets the shown state, since the visual gate cannot hover), `LongTitle` (truncation beside the column and the trailing group at 375 and 1280), `EveryMetadata` (date words, repeat, deadline, start, estimate with tracked, blocked, streak, three fields, origin, three labels, project, every count), `Labels` (one, two, four, one omitted), `Completed`, `Selected`; `CalmToday`, `DetailedToday` and `CalmLabels` are removed. `board.stories.tsx` and `calendar.stories.tsx` (Plan) regenerate. Baselines come from CI's ui-check artifact or `make ui-baselines` (Docker), as for every open change.

**D12. Size and performance.** No dependency. Bundle about −1 KB gzipped: the Detailed branches, `LabelDots`, the settings row and its strings leave; the column, the actions cluster and two media-query hooks come. One extra boolean prop per row and one CSS variable per list; `listPerformance.test.tsx` keeps asserting two re-renders per cursor move, and a new case asserts that toggling the time format re-renders the list once, not per row. Server, image and memory unchanged.

## Data model

Nothing added. `user_prefs.row_detail` stays in the op schema, the TypeScript type, the defaults, the export and the import; it is no longer read or written by the client. No field is renamed or removed; no migration.

## Risks / Trade-offs

- [People who chose Detailed lose it] → the CHANGELOG names the change and what replaces each pill (the panel, the wide layout's columns); the stored preference is kept so a later change could read it again.
- [A 12-hour time column costs 76 px of title on a 375 px phone] → measured in the `LongTitle` story at 375; titles truncate as today, and an untimed list has no column at all. If the measurement shows fewer than 24 characters of title at 375 px in the 12-hour format, the column drops its AM/PM to a smaller cap variant, decided in task 2.2.
- [Revealed actions surprise keyboard users with three new tab stops per row] → the stops exist only on fine pointers from 768 px, `j`/`k` skip them, and the cheat sheet's list section names "Tab: row actions"; `assistiveSemantics.test.tsx` asserts the order.
- [Hover reveal collides with the inline title editor's bar] → the actions are not rendered while `inline` is set (the bar already has Date, Priority, Labels, Project).
- [The faint middle dots fail a contrast audit] → they are decorative generated content, not text; the axe gate runs on every story and ignores `::before` content; items are separated for screen readers by element boundaries.
- [Four open changes modify the same requirements] → deltas written against their post-archive text; task 7.1 reconciles at apply time.
- [`PlanRow` has event rows and projections that `TaskRow` does not know] → `PlanRow` stays as the wrapper for those; only the task row inside it moves to the compact shape.
- [Removing `LabelDots` breaks a caller] → task 2.5 greps and keeps it if the panel or a story still uses it.

## Migration Plan

Pure client change shipped with the next build. No data migration; `row_detail` is kept. Rollback is reverting the commit. Docs screenshots for Today, Upcoming, a project list, the board and Plan are regenerated with `make docs-screenshots` (or come from CI's docs-screenshots job).

## Open Questions

- Whether the 12-hour column shows "9:00 AM" or "9:00a" at 375 px, decided by the measurement in task 2.2 without changing the spec (the spec says "the widest value the user's time format can produce").
- The exact `max-w` of the trailing project name on a 768 px window (12 rem proposed), tunable after the `LongTitle` baseline.
