# Design

## Context

See proposal.md for motivation. Relevant current state:

- `web/src/index.css` holds every token as a hex (or `rgb()` with alpha for the dark priority tints): light on `:root, [data-theme="light"]`, dark twice (the system preference block and the `[data-theme="dark"]` block, kept identical by `theme.test.ts`), then one `[data-accent="…"]` block per theme with fourteen hand-tuned values, then the twelve hues with three values each per mode, then the high-contrast override, then the no-motion attribute. The chart ramp already derives five steps with `color-mix(in oklab, …)` and `web/src/lib/chartRamp.test.ts` re-implements that mix to check it.
- The contrast check (`src/ui/tokens/contrast.ts`, `css.ts`, `pairs.ts`, `contrast.test.ts`) reads the raw declarations as strings and parses `#rgb`, `#rrggbb` and opaque `rgb()` only; a translucent or computed value throws. Every pair in `pairs.ts` is measured in light and dark and for every accent; the high-contrast override is measured at 7:1 for text.
- The token lint (`src/ui/tokens/lint.test.ts`) refuses raw palette classes, fixed white and black, hex literals and literal colour functions in `src/ui` and the screens; `color-mix()` over tokens is allowed. It does not look inside the token blocks of `index.css`.
- The type scale is six steps (hint 11, meta 13, body 15, h3 17, h2 20, h1 24 px, rem based); page titles use `text-h1 font-semibold`; the Focus and Display clocks multiply `--text-h1`. Chips and row counts already set `tabular-nums`.
- Inter 4.1 is bundled at 54 KB as a weight-only variable font: the subset command instances `opsz=14` before subsetting, which drops Inter's optical-size axis (14 to 32) and with it the Display cut that tightens large text.
- Motion is two durations (120 and 250 ms) and one curve (`--ease-calm`); "Reduced motion" caps transitions at 250 ms; `data-motion="none"` zeroes every duration.
- `appearance-preferences` "A theme changes only the accent" and design-system "OpenTodo identity is preserved" fix the neutrals across themes and name the slate family; the browser bar colour is the light accent and the dark canvas (`accents.ts` holds the hex `bar` values and `DARK_BAR`).
- Open changes that also touch `design-system` (`icons-and-section-style`, `inbox-means-unplaced`, `settings-copy`, `ux-audit-three-widths`) modify or add requirements this change does not touch ("Icon catalogue", "Illustrations", "Settings section and row patterns", "Core screens in the workbench" and the audit requirements), so the deltas here cannot collide at archive time. The later refresh changes (`rows-v2`, `sidebar-v2`, `motion-v2`) reference the tone scale and the moment tokens by name and add nothing to the token set.

## Goals / Non-Goals

**Goals:**
- One source value per accent and per hue, every tint derived by a stated rule, so a new theme is three lines and cannot fail contrast silently.
- Neutrals that separate surfaces by lightness in dark mode and read warmer in both, without changing what any theme is allowed to change.
- A tone scale, a display type step, tabular figures and two motion tokens that the following screen changes can cite instead of inventing values.
- The contrast and lint gates stay the only arbiter: every derived value is measured, every literal is refused.

**Non-Goals:**
- Changing any layout, component or screen (later changes).
- A build step that compiles tokens: the browser resolves them (D2).
- Perceptual contrast (APCA) in place of WCAG ratios: the specs and the audit tour use WCAG 2.2 and so does this change.
- Theme-specific neutrals or an accent-tinted canvas (D3).

## Decisions

**D1. OKLCH as the authoring space, `color-mix(in oklch, …)` for derivation.** Every colour token is written `oklch(L C H)` or `oklch(L C H / A)`; derived tokens are `color-mix(in oklch, var(--ot-x) P%, var(--ot-y))` with `P` a named constant. OKLCH gives even lightness steps across hues, so one mix ratio produces usable soft and text steps for all twelve hues and eight accents, which hex cannot. Alternatives: keep hex and derive at build time with a script that writes `index.css` (rejected: a generated stylesheet and a second source of truth, and the workbench could no longer edit a value and see it); relative colour syntax `oklch(from var(--ot-accent) calc(l - 0.08) c h)` (clearer for lightness steps, but its browser baseline is a year younger than `color-mix` and OKLCH; revisit when the audit tour's browser matrix allows it); `oklab` mixing as the chart ramp uses today (fine for lightness ramps, but mixing toward white or black in OKLCH keeps hue, which the soft steps need; the chart ramp moves to OKLCH too so there is one space). Every value is kept inside the sRGB gamut by choice of `C`, so the resolver's clipping never changes a token.

**D2. Resolved in the browser, measured in the tests.** No build step. The tests gain `src/ui/tokens/resolve.ts` (about 120 lines, no dependency): parse `oklch()`, `color-mix(in oklch|oklab, …)`, `var()` chains and alpha; convert through OKLab to linear sRGB; composite a translucent foreground over the pair's background before the WCAG ratio. `css.ts` keeps returning raw declarations and adds a `resolve(tokens, name, bg?)`; `contrast.test.ts` measures resolved values; `chartRamp.test.ts` drops its private mixer for the resolver. Alternative: a snapshot of resolved hex values committed next to the CSS (rejected: a second file to keep in step, which is what the test exists to avoid).

**D3. Neutrals: same family, lower chroma, lifted dark canvas, fixed across themes.** Light: canvas `oklch(0.985 0.003 250)`, surface and raised white, sunken `oklch(0.965 0.004 250)`, text strong `oklch(0.15 0.02 260)`, text `oklch(0.24 0.025 262)`, muted `oklch(0.47 0.028 262)`, faint `oklch(0.52 0.026 262)`, border `oklch(0.91 0.008 255)`, border-soft `oklch(0.94 0.006 255)`, border-input `oklch(0.62 0.03 262)`. Dark: canvas `oklch(0.17 0.016 262)` (today's canvas is `oklch(0.13 0.042 265)`, nearly black and markedly blue), surface `oklch(0.22 0.018 262)`, raised `oklch(0.27 0.02 262)`, sunken `oklch(0.14 0.014 262)`, text strong white, text `oklch(0.95 0.008 262)`, muted `oklch(0.74 0.02 262)`, faint `oklch(0.68 0.022 262)`, border `oklch(1 0 0 / 0.10)`, border-soft `oklch(1 0 0 / 0.06)`, border-input `oklch(0.60 0.02 262)` (opaque, 3:1). The chroma drop and the slightly lower hue angle are the "warmer grey" of Linear's refresh; the family is still slate so "OpenTodo identity is preserved" keeps its words and gains the lifted canvas. The values are starting points: the task that tunes them in the workbench may move any value within 0.02 of L and 0.006 of C as long as every pair passes. Alternative: tint the dark canvas with the accent at 3 to 4 percent chroma, as the analysis suggested (rejected: `appearance-preferences` "A theme changes only the accent" and the bar colour rule both require neutrals that do not follow the theme, and the eight themes would need eight dark baselines; a fixed warm tint gives most of the effect).

**D4. Accents declare three values, the rest derive.** Per `[data-accent]`: `--ot-al-accent` (light accent, also the bar colour), `--ot-ad-accent-text` (the bright dark-mode accent used for links, the focus ring and the chart base) and `--ot-a-on-accent` (white for every theme today; declared so a light accent can switch to dark text). Derived, in the mapping blocks that already exist: `accent-hover = mix(accent 86%, black)`, light `accent-soft = mix(accent 10%, surface)`, light `accent-soft-text = mix(accent 80%, black)`, light `focus = mix(accent 85%, white)`, dark `accent = the light accent` (as today, buttons keep their depth in dark), dark `accent-soft = mix(accent-text 14%, surface)`, dark `accent-soft-text = mix(accent-text 80%, white)`, dark `focus = accent-text`, `chart-base` as today. The ratios are declared once as `--ot-mix-*` custom properties and read back by the contrast test, which fails naming the accent, mode and pair when a derived step misses its minimum; an accent may then override one derived token with an explicit value next to a comment, and `theme.test.ts` counts those overrides so they do not grow unnoticed. Graphite keeps an explicit dark `accent` (today's `#475569`, lighter than its light accent) through that override. Alternative: keep fourteen values per accent (rejected: that is the problem).

**D5. Hues declare one solid per mode, soft and text derive.** Light `soft = mix(solid 14%, surface)`, `text = mix(solid 68%, black)`; dark `soft = mix(solid 22%, canvas)`, `text = mix(solid 78%, white)`. Yellow and lime, whose light text step is the hard case for 4.5:1 on their soft step, get explicit overrides if the measured ratio misses; the test names them. The twelve chip pairs stay in `pairs.ts` unchanged. The high-contrast override keeps its outlined soft steps (pure surface) and its explicit text steps, re-expressed in OKLCH at the same measured ratios.

**D6. The tone scale is the four text tokens plus a soft border.** `text-strong`, `text-default`, `text-muted`, `text-faint` are named the tones; an icon takes the tone of its text (`currentColor`); a divider is `border-soft`, a container edge `border-default`, a control edge `border-input`. The rule: to make something quieter, step down one tone; never `opacity-*`, `text-[…]`, a palette grey or a raw alpha. The style lint refuses `opacity-` utilities on text-bearing elements and `/NN` alpha suffixes on text and border tokens in screens and `src/ui` (the lint already rejects raw colours; this adds the two patterns, with a `tone-lint-allow` marker for the few true opacity cases: a dragged ghost, a disabled control, the scrim). Alternative: opacity levels as the analysis suggested, as Linear does (rejected: text at 60 percent opacity measures differently on every surface, the contrast pairs would multiply by the surfaces, and `faint` already is the measured equivalent).

**D7. Type: a display step, tracking, weight 600, optical sizing.** New `--text-display: 1.75rem` with line height `2.125rem` and `letter-spacing: -0.02em`; `h1` gains `-0.015em`, `h2` `-0.01em`; headings h1 to h3 and display are weight 600 (`font-semibold`, as page titles are today). The clocks multiply `--text-display` instead of `--text-h1` (`.focus-clock`, `.display-clock`), which leaves their rendered size the same within rounding. `font-optical-sizing: auto` on `html`, and the subset command stops instancing `opsz=14`, keeping both axes so text at the display size uses Inter's Display cut automatically. Budget: the two-axis Latin subset is expected at 95 to 110 KB (the weight axis alone is 54 KB; Inter's optical-size axis roughly doubles the outline data); it is measured in task 3.2 and kept if at most 120 KB (one request, precached, cached by hash). Above that, the fallback is to keep the weight-only file and add a second static instance at `opsz=32`, weight 600 only, subset the same way (about 15 KB), declared as a second `@font-face` with the same family name and a `font-weight: 600` range used by the display step only. Which path was taken is recorded here and in `docs/design-system.md`. Alternative: a second typeface for display (rejected: a new file, a new licence and a second voice).

**D8. Tabular figures everywhere a number is shown.** Tailwind's `tabular-nums` becomes part of the primitives that print numbers: `Chip`, `Count`, the row metadata line, `ListGroupHeader` counts, `StatTile`, the calendar time rail and event times, the sidebar counts, the clocks. A unit test over those primitives asserts the class; screens print numbers through them. Alternative: `font-variant-numeric: tabular-nums` on `body` (rejected: it also widens prose digits in notes and comments where proportional figures read better).

**D9. Motion tokens.** `--ease-spring: cubic-bezier(0.34, 1.3, 0.64, 1)` (a light overshoot that settles, no physics library) and `--duration-moment: 400ms`. `--duration-ui` and `--duration-emphasis` stay. "Reduced motion" is restated: ordinary transitions stay within 250 ms; the one longer duration is the moment, used only by the completion sequence `motion-v2` builds, and under reduced motion or `data-motion="none"` it collapses to the same opacity-only rule as everything else (the reduced-motion media block already strips transform transitions; the no-motion block gains `--duration-moment: 0ms`). Alternative: a spring implemented with the Web Animations API keyframes (deferred to `motion-v2`, which may add it for the completion pop; the curve token is enough for sheets and popovers).

**D10. Lint on the token blocks.** `lint.test.ts` gains a rule over `index.css`: inside the token blocks (`:root`, the two dark blocks, every `[data-accent]`, the hue table, the high-contrast override) a declaration's value may be `oklch(…)`, `color-mix(in oklch, …)` or `color-mix(in oklab, …)` over `var()` tokens, `var(…)`, `transparent` or a length or time; `#…`, `rgb()`, `hsl()` and named colours fail naming the line. The brand yellow of the coffee button becomes `oklch(0.9 0.19 100)` with no exception.

**D11. Bar colour stays hex data.** `accents.ts` keeps `bar` and `DARK_BAR` as hex, since the browser bar colour is written into `meta[name=theme-color]` and the manifest; `theme.test.ts` asserts each equals the resolved light accent and the resolved dark canvas within a rounding tolerance, so the data cannot drift from the tokens.

**D12. One baseline regeneration.** The neutral change moves every pixel of every story, so the visual gate is regenerated once, after the values are tuned (task 2.5), from CI's ui-check artifact or `make ui-baselines` with Docker; no story is edited for this change beyond the foundations.

**D13. Spec placement.** All deltas are in `design-system`. "Semantic design tokens", "OpenTodo identity is preserved", "Accessible contrast in both themes", "Bundled typeface without network access", "Comfortable reading scale", "Secondary text is one size", "Reduced motion" and "Design workbench" are modified with their full text; none of them is modified by an open change (checked against every `openspec/changes/*/specs/design-system/spec.md` on 21 October 2026). The tone scale, the derivation rules and the moment tokens are ADDED requirements so later changes can cite them by name.

**Interface budget.** No screen changes: zero rows of chrome, properties, destinations, scroll regions or shortcuts are added. The display step changes the size of nothing until `page-rhythm` applies it to titles.

**Data model.** None. **Size.** CSS: the accent blocks drop from about 1.9 KB to 0.4 KB raw, the hue table from 1.6 KB to 0.6 KB; net about 2 KB gzipped smaller. JS: `resolve.ts` is test-only (the workbench exclusion test keeps it out of the production build). Font: see D7. Server binary and image: unchanged except the font file. Runtime memory: unchanged.

## Risks / Trade-offs

- [A derived step misses 4.5:1 for one hue or accent] → the contrast test names it; one explicit override per failing token, counted by `theme.test.ts`, keeps the exception visible.
- [OKLCH and `color-mix` on an old WebView] → both are Baseline 2023; the installed app targets evergreen browsers and the native shells (`native-shells`) use the system WebView of Android 12+; a one-line `@supports not (color: oklch(0 0 0))` fallback sets the six surface and text tokens to hex so the app stays readable, not themed, on anything older.
- [Font file grows beyond the budget] → D7's fallback path; measured before merge.
- [Every baseline changes at once] → one regeneration, reviewed on the ui-check report's contact sheet rather than story by story.
- [The warmer neutrals read as a different app to existing users] → the change is small (chroma, not hue), the CHANGELOG names it, and the high-contrast override is unchanged.
- [Tone lint false positives] → the `tone-lint-allow` marker, and the lint names file and line.

## Migration Plan

Stylesheet only; no data, no server change. Deploy with any release. Rollback: revert the stylesheet, the font file and the test resolver together (the baselines of the previous state are in history). The allow-lists in `notYetMigrated.ts` do not change size; the lint's new rules apply to every file at once because the screens already use tokens.
