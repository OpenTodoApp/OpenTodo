# Design

## Context

See proposal.md for why. What exists today:

- **Page template.** `PageHeader` renders the title at `text-h1` (24 px, 600) with `meta` inline beside it in `text-meta text-muted` (`data-page-meta`); `PageBody` is the frame (`PAGE_FRAME`: `mx-auto w-full max-w-[80rem]` plus `px-4 md:px-8`) and `data-page-body="list|form|wide|full"` gives every child except the header its width (48, 42, 72 rem or none), left-aligned in the frame (`ux-feedback-2` D7, "One page frame"). The frame step of `scripts/e2e-views.mjs` pins that the header and the content start, and the actions end, at the same place on every page. The shell's content column is `#content` inside `main[data-app-frame]`; the panel is a sibling column of 26 rem from 1024 px and 30 rem from 1440 px (`app-shell` "Panel width and expansion"); the sidebar is 15 to 22.5 rem, 16 rem by default.
- **Group headers.** `ListGroupHeader` renders the title at `text-body font-semibold` in `text-default`, `text-danger` for Overdue, with the count in `text-meta text-faint tabular-nums` and `hover-reveal` trailing actions. `listGroups.ts` builds Today as Overdue, Today, This Evening, Blocked (Blocked collapsed by default through `BLOCKED_OPEN_KEY`); Overdue and Blocked imply nothing for their rows (`calm-rows` D3).
- **Calm rows** colour the date muted except overdue (danger) and a timed task due today (accent); Detailed rows use danger, success, violet and muted (`calm-rows`, "Metadata language").
- **Bulk actions** write one batch with a ten-second Undo toast and `Ctrl`/`⌘`+`Z`; the Date items (today, tomorrow, next week, no date, pick a date) apply without review (`bulk-actions`).
- **"Overdue"** is the heading in `listGroups.ts`, `DailyCheck.tsx`, `DisplayScreen.tsx`, the digest templates (`internal/mail/templates/digest.*.txt`, placeholder `Overdue`) and their goldens, the weekly review's Look back step, and `docs/views.md`, `docs/today-and-upcoming.md`.
- **Type scale.** `design-system` "Comfortable reading scale" fixes body 15 px and metadata 13 px and forbids text under 12 px outside key badges. `tokens-v2` (another change of this batch) adds a `display` step for page titles; this change references it and falls back to `text-h1` with `tracking-tight` and 600 weight until it lands.
- **Open changes being archived within the hour.** `ux-feedback-2` modifies "Page template"; `inbox-means-unplaced` modifies "Standard views"; `calm-rows` and `time-tracking` modify "Metadata language"; `lean-chrome` modifies "Nothing between the header and the list"; `close-the-day` modifies the review's "Daily check". The deltas here are written against those changes' text (see D9).

## Goals / Non-Goals

**Goals:**
- A visible hierarchy on every list page from type and space alone: title, lead line, group labels, rows.
- No list page left-aligned in a column with a third of it empty, without undoing `ux-feedback-2`'s still header on project layouts.
- Earlier tasks shown as a fact with a way out, not as an alarm.
- No new colour, no new chrome row, no new scroll region, no new key.

**Non-Goals:**
- Row anatomy and chip language (`rows-v2`), token values (`tokens-v2`), reflow motion beyond the frame slide (`motion-v2`), phone chrome (`phone-v2`).
- Changing which tasks Today, Upcoming or the Inbox list, or when a task is "earlier" (the logical day of `date-time-preferences` stays the rule).
- The filter query language, the REST API, exports: `overdue` the keyword and `completed late` the measurement stay.

## Decisions

**D1. The lead line is inside the header, not a chrome row.** The title moves to its own line at the display step and `meta` renders under it as the lead line at the metadata size in the muted tone. The header is still one element (`data-page-header`), so `budget.test.tsx`, which counts chrome elements above the first row, keeps counting one header and one quick add; the interface budget's "2 rows of chrome" is a count of elements, stated so in `docs/interface-guide.md`. Height: the title line grows from 2 rem to the display line height (2.25 rem) and the lead line adds 1.125 rem plus a 0.25 rem gap, 1.625 rem in all, and the header's top padding drops by 0.25 rem, so a page with meta is 1.375 rem (22 px) taller and a page without meta (Inbox) is 0.25 rem taller. The "No desktop top bar" scenario ("first task within the top 160 px" on Inbox) is measured on a page without meta and is unchanged. Alternatives: keep meta inline (rejected: the title then competes with a sentence on the same line, which is the sameness the proposal names); a lead line only on Today (rejected: the project's members and a label's count want the same place).

**D2. Group headers are labels.** The title becomes `text-meta font-semibold` in `text-muted`; generated groups add `uppercase tracking-wide`, named groups stay sentence case (uppercase of user text looks wrong with long names, accents and other scripts; Todoist renders section names in sentence case while date groups read as labels). 13 px satisfies "Comfortable reading scale" (no text under 12 px). The count stays `text-faint tabular-nums`. The row height of the header stays `min-h-9` so nothing moves vertically. `ListGroupHeader` gains `kind: 'generated' | 'named'` and `actionsAlwaysVisible`; `tone="danger"` is removed from its props, so a group cannot be red again by accident (`patterns.test.tsx` asserts it). Alternative: 11 px small caps as in Linear (rejected by the reading-scale requirement).

**D3. Two frames, one rule each.** The conflict: `ux-feedback-2` left-aligned lists so the title does not move between a project's list, board and timeline, and the audit found that left alignment leaves wide screens empty. Both are right for the pages they look at. A page without a layout switch has nothing to stay still *for*, so its frame narrows to the content width plus padding and centres; a page with a layout switch keeps the shared 80 rem frame, and its list layout gets the `wide` width (72 rem) so rows run to near the frame's right edge like the board does. `PageBody` and the task lists mark `data-page-frame="standalone|layout"`; one CSS rule gives a standalone frame `max-width: calc(var(--page-width) + 2 * var(--page-gutter))`. Widths with the default 16 rem sidebar and `px-8` gutters (2 rem each side):

| Window | Content column | Panel | Standalone frame, panel closed | Standalone frame, panel open | Layout frame |
| --- | --- | --- | --- | --- | --- |
| 1024 px | 48 rem | 26 rem | 48 rem (fills; list 44 rem) | 22 rem (fills; list 18 rem) | 48 rem |
| 1280 px | 64 rem | 26 rem | 52 rem, 6 rem each side | 38 rem (fills) | 64 rem |
| 1440 px | 74 rem | 30 rem | 52 rem, 11 rem each side | 44 rem (fills) | 74 rem |
| 1536 px | 80 rem | 30 rem | 52 rem, 14 rem each side | 50 rem (fills) | 80 rem |
| 1920 px | 104 rem | 30 rem | 52 rem, 26 rem each side | 52 rem, 11 rem each side | 80 rem |

Settings pages (42 rem) and the field-columns list (72 rem) follow the same rule with their own width. Alternatives considered: centre every page including projects and animate the title's jump between layouts (rejected: it undoes a fix the user asked for the day before); keep every page left-aligned and fill the right with nothing (rejected: the audit's finding); a single narrower frame for everything (rejected: boards and timelines need the width).

**D4. The frame moves when the panel docks.** The brief asked that the title not move when the panel opens. The table shows it cannot both stay still and stay centred on windows wider than the frame plus the panel: at 1920 px the frame is 26 rem from the left with the panel closed and 11 rem with it open. Decision: the frame re-centres with a 250 ms slide on the `transform`/`margin` of the frame (the emphasis duration, `ease-calm`), instant under reduced motion; at 1280 px and below nothing moves because the frame already fills the column. Todoist and Things both shift the list when their detail pane opens. Alternative: reserve the panel's width even while it is closed (rejected: the list would sit left of centre on every wide screen, which is the problem being fixed).

**D5. Earlier.** The word "Earlier" states a fact (these were planned for earlier days) and is the heading Things, Apple Reminders and the iOS calendar use for past items. The group's label is muted like every other; the date on each row stays in the danger tone, so how late a task is remains visible on the row (`calm-rows` D3 is kept: Earlier implies nothing). The header's two actions are always visible because they are the group's purpose, not a secondary control; they are `Button variant="ghost" size="sm"` at the metadata size and count as the header's trailing slot, so no row is added. Default collapse above five tasks: five is the number of rows a person can decide on at a glance in the audit's rubric; at six or more the group turns into a wall that pushes today's tasks below the fold, and collapsed it still says "8" with the two actions, so nothing is hidden silently. The default applies only on a device with no stored state for the group key (`EARLIER_KEY`), like Blocked; opening or closing it is remembered per device as every group is. Alternatives: never collapse (rejected: the wall); a "Show n more" after three (rejected: a third pattern for groups).

**D6. Group actions reuse the bulk batch.** "Move all to today" is the bulk Date → Today path and "Reschedule…" opens the bulk Date menu's choices, both applied to the group's task ids instead of the ticked set, through the same `applyBatch` and the same Undo stack, so offline queuing, per-field convergence, the repeating-task and subtask rules and `Ctrl`/`⌘`+`Z` are inherited. The selection is untouched (the batch takes ids, not the selection). Read-only tasks (a viewed shared project) are skipped and counted in the toast, as bulk actions skip them. A deadline-only task gets `due = today` and keeps its deadline (nothing else would make it leave Earlier honestly). Palette commands: "Move earlier tasks to today" and "Reschedule earlier tasks…", registered in `app/palette/registry.ts` without keys (the shortcut registry lists keyed shortcuts only, so there is nothing to conflict), offered while `groupToday(...).overdue.length > 0`. Alternative: a dedicated "Earlier" review screen (rejected: a flow for a decision that takes one click).

**D7. The due ladder.** Calm rows today jump from muted ("Tomorrow") to danger (a red date) overnight; a task due today without a time is muted, so the day a task is due is the quietest it ever looks. The ladder is four steps on existing tokens: later → `text-muted`, tomorrow → `text-default`, today → `text-accent` (timed or not), earlier → `text-danger`. It is stated as an ADDED requirement that takes precedence over the Calm tones of "Metadata language", because `calm-rows` and `time-tracking` both modify that requirement and are archiving; task 7.1 folds the ladder into "Metadata language" once they are archived. Detailed rows keep their four tones. Implementation: `dateTone(task, today)` in `web/src/lib/rowDetail.ts` (or beside `facets.ts`), one function used by `TaskRow`, the board card and the display, pinned by `rowDetail.test.tsx`. Alternative: an icon or a dot for "soon" (rejected: rows carry no icon-only glyphs, and a fifth chip is noise).

**D8. Words.** One table in `web/src/lib/settingsCopy.ts`'s neighbour `web/src/lib/words.ts` is not needed: the strings are few. Replacements: group "Overdue" → "Earlier" (`listGroups.ts`, `DailyCheck.tsx`, `DisplayScreen.tsx`); the review's Look back note "n overdue" → "n from earlier"; Carry over's line → "still open from earlier"; the digest's section heading → "Still open from earlier" (`digest.en.txt` and the five others, the placeholder name `Overdue` in `digest.go` can stay as a Go identifier but the rendered word changes; goldens regenerated and reviewed). Kept: Statistics "completed late" and "slipped" (measurements the `statistics` spec defines), the deadline countdown "nd over" (a measurement), the filter keyword `overdue` (a language), API field names. Docs: `docs/views.md`, `docs/today-and-upcoming.md`, `docs/method/rhythms.md`, `docs/review-and-statistics.md`, `docs/interface-guide.md` say "Earlier" and explain the ladder. Translations: the five catalogs through `node scripts/i18n-check.mjs`; the German, French, Spanish, Italian and Portuguese words are chosen in the task, with "Earlier" rendered as the language's word for "from earlier days" rather than a literal "earlier".

**D9. Spec placement against archiving changes.** "Page template" is MODIFIED with `ux-feedback-2`'s full text as the base (its "List, board and timeline keep the header still" and "Wide board inside the frame" scenarios are kept). "Standard views" is MODIFIED with `inbox-means-unplaced`'s full text as the base (its Inbox line and quick-add announcement scenarios are kept). "Group headers" and "Deadlines in Today" are modified by no open change. The due ladder and the words are ADDED requirements so that "Metadata language" (modified by `calm-rows` and `time-tracking`) and "Daily check" (modified by `close-the-day`) are not touched twice; task 7.1 reconciles the ladder into "Metadata language" at archive. If any of those changes' text differs at apply time, the apply re-reads the archived requirement and keeps this change's additions on top.

**D10. Interface budget.** Rows of chrome above the first item: 2 (the header element, now with a lead line inside it, and the quick add); nothing is added between the quick add and the first group. Task properties visible by default: unchanged (the ladder recolours a date, it adds nothing). Primary sidebar destinations: unchanged. Vertical scroll regions: unchanged (the frame narrows, it does not scroll). Shortcuts: none added; two palette commands without keys. Phone: the lead line is the bar's subtitle, the group label style and Earlier apply as on desktop, the actions wrap under the label at 375 px without horizontal scroll.

**D11. Size and data.** No dependency. CSS and strings only: the main bundle changes by under 1 KB gzipped; the server binary changes by the digest template words. No op, field, migration or API change; the only writes are the batches a user asks for, through the existing bulk path.

## Risks / Trade-offs

- [The title moves when the panel docks on wide screens] → the slide makes the move read as the panel arriving; nothing moves at 1280 px and below; stated in the interface guide.
- [Project lists stay left-aligned in the 80 rem frame] → the list layout spans 72 rem so the right side is used; `rows-v2` puts the trailing counts and hover actions at the row's right edge, which wide rows want.
- [Uppercase labels hurt readability for some readers] → 13 px semibold with 0.04 em tracking, never for user text, and the label is also the `h2` text for assistive technology in its original case (`aria-label` is not used; CSS `text-transform` keeps the DOM text).
- [Hiding Earlier by default above five tasks hides work] → the count and both actions stay visible; the state is remembered once touched; Close the day and the Daily check still list the tasks in full.
- [Someone wants "Overdue" back] → the word is a translation key, trivial to flip; the measurements keep their words.
- [Baselines] → every touched story (Screens/Today, Upcoming, Project list, Settings, Page header, Group header) changes; baselines come from CI's ui-check artifact or `make ui-baselines` (Docker).

## Migration Plan

Nothing stored changes. Per-device group collapse state keeps its keys; the new `EARLIER_KEY` starts unset, so the default applies once per device. Rollback: revert the commit; no data to migrate back. Upgrade note in the CHANGELOG: "Overdue is now Earlier" with the two new actions.

## Open Questions

- The exact German, French, Spanish, Italian and Portuguese words for "Earlier" and "n from earlier" are chosen with the translation task; they do not change the specs.
- Whether the collapse threshold of five should follow the Compact density (more rows fit) can be decided after use without changing the specs' shape.
