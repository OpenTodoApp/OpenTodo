# Design

## Context

See proposal.md for motivation. What exists today and shapes the approach:

- Today's focus is three task ids on the synced `review` row (`focus_date`, `focus`), read with `storedFocus` and `focusTasks` in `web/src/lib/review.ts` and shown on the Loop home and the Daily check. There is no screen to work one of them.
- `time-tracking` (a separate change, implemented first) owns the `time_entries` collection and the client functions that start, pause, resume and stop an entry on a task through `mutate()`. This change calls them and never writes an entry field itself.
- Routes are a discriminated union in `web/src/app/router.ts` and rendered by `Shell.tsx`; a view registers its keys with `useShortcutScope('view', …)` against ids in `web/src/lib/shortcuts.ts`, and `VIEW_SCOPES` tells the conflict test which scopes a view hosts. The triage view (`web/src/app/TriageView.tsx`) is the model: one task, no list, `view`-scoped keys.
- In-app reminders (`web/src/app/ReminderToasts.tsx`) already show a system notification through `swRegistration().showNotification` when the tab is hidden, tagged so a push never duplicates it; `web/public/push-sw.js` handles `notificationclick` for reminders and the test notification.
- Device-local state that is never an op lives in Dexie tables beside the synced ones (`assistantThreads`, `pickHistory`, `attachmentBlobs`) or in `meta` through `getMeta`/`setMeta`; `clearLocalData()` wipes them on sign-out. Schema version is 20 (time-tracking's `timeEntries`).
- Personal preferences are additive fields on `user_prefs` (`Schema` in `internal/sync/ops.go`, `UserPrefs` in `web/src/lib/types.ts`, defaults in `web/src/lib/ops.ts`, writes through `web/src/lib/userPrefs.ts`), edited in `web/src/app/PreferencesPanels.tsx` (Language, Start view, Keyboard cards of the General section).
- The icon set is vendored (`web/src/ui/icons/names.json`, regenerated by `scripts/icons-sync.mjs`); it has `clock`, `alarm-clock`, `hourglass`, `coffee`, `check`, `chevron-right`, `x`, but no `timer`, `play` or `pause`.
- The interface budget (docs/interface-guide.md): two rows of chrome above a list, three scroll regions, six primary destinations, every shortcut registered without a conflict.

## Goals / Non-Goals

**Goals:**
- One screen, one pure timer model that every scenario can be tested against with a fake clock, no dependency, no asset.
- A hard seam to time tracking: the Focus code depends on an interface, and the app works unchanged when nothing implements it.
- Every effect of a session end (done state, tone, notification, entry stop) derives from one state transition recorded in the local store, so a reload, a hidden tab or a second tab cannot double it.
- Device-local timer state, synced preferences, nothing new on the server beyond schema fields.

**Non-Goals:**
- No change to the time entry entity, its REST routes or its reports (`time-tracking`).
- No change to the Loop home or the Daily check (the Loop home is being reshaped by `loop-home-refresh`; this change only reads the focus list).
- No background timer in the service worker: the worker cannot schedule a notification for later; the page computes from the clock when it runs.
- No idle detection, no statistics of sessions, no sidebar destination.

## Decisions

**D1. One pure timer model, driven by the clock.** `web/src/lib/focus/timer.ts` holds a `FocusState` record (`taskId`, `mode`, `phase: 'idle' | 'work' | 'break' | 'done'`, `startedAt`, `accumulatedMs` before the current run, `paused`, `cycle`, `plannedMs` or null for Flowtime, `endedKind`, `lengthMinutes` for Countdown, `entryId`) and pure functions over it with an explicit `now`: `elapsed(state, now)`, `remaining(state, now)`, `start`, `pause`, `resume`, `finish(state, now, prefs)` (work → break, break → work, long break every N), `takeBreak`, `complete`. Nothing counts ticks: the screen re-renders on a one-second interval only to display, and recomputes from `now` on `visibilitychange`, on focus and after a reload, which is what the "Tab hidden through the end" and "Reload" scenarios need. Alternative: a `setInterval` that decrements a counter. Rejected: wrong after a sleep and in throttled tabs.

**D2. The state lives in one Dexie row.** A new table `focus: 'id'` (schema version 21) with one row `current` of type `FocusState`, read live with `useLiveQuery`, written on every transition; it is in no synced table list, not exported, and `clearLocalData()` drops it with the rest. Alternative: `meta` key. Rejected: a typed table reads better in tests and the live query is free. Alternative: `localStorage`. Rejected: the app keeps every local record in Dexie, and the row must survive private-window storage pressure the same way the outbox does.

**D3. The session-end transition is written once and effects follow the row.** `useFocusTimer()` (in `web/src/app/focus/`) owns the interval and the visibility listener. When `remaining(state, now) <= 0` it calls `finish` inside a Dexie `rw` transaction that re-reads the row and gives up if it is no longer in that run (`startedAt` differs or `phase` is already `done`). Effects are then driven by the row change: the done state renders from `phase === 'done'`; the tone plays when the row transitions to done in a visible tab whose `endedAt` is less than five seconds old (so a tab returning an hour later shows the done state silently); the notification is shown with `tag: 'focus:<startedAt>'`, which the browser collapses across tabs ("Two tabs" scenario). The time entry is stopped by the same code path with the entry id from the row; `time-tracking`'s stop is idempotent per field, so a double call converges.

**D4. The logger seam.** `web/src/lib/focus/logger.ts` declares `interface FocusLogger { start(taskId): Promise<string | null>; pause(id): Promise<void>; resume(id): Promise<void>; stop(id): Promise<void>; running(id): Promise<boolean> }` and a `noopLogger` whose `start` returns `null`. `web/src/lib/focus/index.ts` exports `focusLogger`, set to the `time-tracking` adapter when `web/src/lib/timeEntries.ts` exists in the build (a static import behind one module) and to `noopLogger` otherwise. The Focus screen never imports time tracking directly. This is the degraded behaviour the proposal names: with `noopLogger` the row's `entryId` stays null and the "logged" line is not rendered. `running(id)` lets the screen notice an entry stopped elsewhere ("Entry stopped elsewhere" scenario) by checking on each remote sync of the entries table.

**D5. Preferences as eight additive `user_prefs` fields.** `focus_mode` (string: `pomodoro` | `flowtime` | `countdown`, default `pomodoro`), `focus_work_minutes`, `focus_short_break_minutes`, `focus_long_break_minutes` (numbers, 1–180, defaults 25/5/15), `focus_long_break_every` (number, 1–12, default 4), `focus_auto_start` (string: `none` | `breaks` | `work` | `both`, default `none`), `focus_break_after_minutes` (number, 0 = off, else 15–240, default 0; the switch in Settings turns it on with 90 when the stored value is 0), `focus_sound` (string: `off` | `on`, default `off`). Added to `Schema["user_prefs"]` with kinds `kString`/`kNumber`, to `UserPrefs` and `USER_PREFS_DEFAULTS`, read through `useFocusPrefs()` in `web/src/lib/focus/prefs.ts`, which maps unknown or out-of-range values to the defaults without writing (the "Unknown mode from a newer client" scenario). Bounds are checked in the settings card before `mutate`, and the server keeps its generic kind check only, like the existing preference fields. The Countdown length is not a preference: it is remembered in the `focus` row (`lengthMinutes`) because it is chosen per session on a device. Alternative: one JSON string field. Rejected: the schema is per field and LWW per field is what the "Concurrent edits" scenario needs.

**D6. The screen is the triage view's shape.** `web/src/app/focus/FocusView.tsx` renders `PageBody width="list"` with `PageHeader title="Focus"`, `meta` = the mode name, actions `Start/Pause` and `Complete`, overflow with three checked mode items (`MenuItem checked`, disabled with a description while a session runs), "Change task", "Settings" (`/settings/general`) and Help (`openHelp('focus')`). Below: the timer card (digits in `text-display font-semibold tabular-nums`, the phase line, the buttons), then the task: title, project chip, due tone text, notes rendered read-only with `Markdown` (a click opens the task panel for editing, so the editor's keymap never meets the view's Space), subtasks as the checklist from `useSubtasks` with the panel's row component. The task panel stays available (`openTaskPanel`) and its keys keep their `panel` scope. Alternative: render `TaskDetail` inline. Rejected: it carries tabs, the composer and the property chips; the budget wants at most seven properties and this screen shows five (title, project, due, notes, subtasks).

**D7. Shortcuts.** Registry entries in `web/src/lib/shortcuts.ts`:
- `go.focus`, keys `['g Shift+F']`, section `go`, scope `global`: "Go to Focus: one task, a timer, a break when you need one". No existing `g` sequence uses `Shift+F`; `project.fields` is a bare `Shift+F` in the project view and never meets a `g` prefix.
- In a new section `focus` ("Focus"), scope `view`, `views: ['focus']`: `focus.toggle` `['Space']` "Start or pause the session", `focus.complete` `['Enter']` "Complete the task and end the session", `focus.break` `['b']` "Take a break now, or end the break", `focus.next` `['n']` "Next task of today's focus", `focus.escape` `['Esc']` "Back to the previous view (the session keeps running)", `hidden: true`.
- `VIEW_SCOPES.focus = []`: no list, board or calendar, so the view's Space, Enter, `b` and `n` never meet `list.tick`, `list.open`, `list.blocked-by` or `list.park`; `panel.escape` keeps shadowing `focus.escape` while the panel is open, exactly as `triage.escape` works. `shortcuts.test.ts` proves there is no conflict.
`Shell.tsx` maps `go.focus` to `go({ view: 'focus' })`; the route is `{ view: 'focus'; id?: string }` parsed from `/focus` and `/focus/<id>`.

**D8. Entry points.** `TaskDetail.tsx` gains `MenuItem label="Focus on this task" icon="clock"` before "Duplicate"; `palette/registry.ts` gains `{ label: 'Go to Focus', route: { view: 'focus' }, shortcut: keysOf('go.focus') }` among the navigation commands and `task:focus` ("Focus on {title}") among the selected-task commands, both running `navigate`. No sidebar item: the budget's six primary destinations are spoken for, and the More group is a method-mode table in `app-shell` this change does not touch.

**D9. Task selection is a pure function.** `nextFocusTask(focusIds, tasks, currentId)` in `web/src/lib/focus/select.ts` returns the first open, live task of the focus list after `currentId` (or the first when `currentId` is not in the list), else `null`. The picker for "Change task" and the empty state is a `ComboboxPanel<Task>` over open tasks, built like the Blocked-by picker in `task-detail/Properties.tsx`, with the picker's recency ranking (`pickHistory` context `focus`).

**D10. The break reminder is a watcher mounted by the Shell.** `web/src/app/focus/BreakReminder.tsx` sits beside `ReminderToasts` and observes the `focus` row: while `phase === 'work'` and not paused, continuous work = `elapsed(state, now) - state.breakResetMs`; when it passes `focus_break_after_minutes` (and the per-session `remindedAt` on the row is older than the length) it shows a `ToastRegion` notice with "Take a break" (`takeBreak`: stop the entry, phase `break` with the short break length) and "Not now" (writes `remindedAt = now`). `takeBreak` from a break and the end of a break set `breakResetMs` so the count restarts. The notice is a toast like the app's other notices (`app-shell` "Notices are toasts") and is reachable with Tab; it moves focus only when the user is not typing, as the reminder toasts do.

**D11. Tone with the Web Audio API.** `web/src/lib/focus/tone.ts` creates one `AudioContext` lazily on the first Start click (a user gesture, so autoplay rules allow it) and plays two sine notes (660 Hz and 880 Hz, 120 ms each, a 20 ms gain ramp) through a `GainNode` at 0.2. About 0.4 KB, no file, no network. In tests `AudioContext` is stubbed and the call is asserted, not heard. Alternative: a bundled `.mp3`/`.ogg`. Rejected: 10–30 KB in the bundle and the precache for a two-note cue.

**D12. Notification click.** `push-sw.js` gets a third `notificationclick` case: when `d.url` is set, focus an existing window and `navigate(d.url)`, else `openWindow(d.url)`. The Focus notification sets `data: { url: '/focus' }`. Nothing goes through the server; `notifyIfHidden`'s precondition (`Notification.permission === 'granted'`) is reused, and unlike reminders there is no push counterpart, so the "push covers this device" check is not applied.

**D13. Accessibility.** The digits are `aria-hidden`; a visually hidden `role="status"` (`aria-live="polite"`) element receives the announcement text at the moments the spec lists (start/resume, every five minutes, one minute left, end), computed in the model (`announcementAt(state, now)` returns the text to announce or null, so the test is a table). The done state is a `section` with `aria-labelledby` its heading and moves focus to its first button through the same `keepFocus` rule `ReminderToasts` uses. Motion: the only transition is the phase line fade, inside the motion tokens.

**D14. Stories and tests.** `focusView.stories.tsx` under `Screens/Focus` with "Running", "Done" and "Choose a task", seeded through `withSeed` and `withClock` from `app/stories/fixtures.tsx`, giving the light/dark × 375/1280 baselines and the axe gate. `timer.test.ts` covers the model with a fake clock; `focusView.test.tsx` renders the Shell with fake-indexeddb for the screen scenarios; `breakReminder.test.tsx` the watcher; `shortcuts.test.ts` the registry; `budget.test.tsx` and `pageTemplate.test.ts` gain the view.

## Data model

- `user_prefs` (synced, personal scope): eight additive fields as in D5; strings and numbers, no content, never encrypted, included in the export with the row. No field renamed or removed.
- Device-local Dexie table `focus` (one row `current`), never an op, never exported, cleared on sign-out.
- `time_entries`: read and written only through `time-tracking`'s functions; this change adds no field there.
- No change to `task`, `review` or any other entity. No migration on the server; the client's Dexie upgrade adds one empty table.

## Size and resources

No dependency. Web bundle about +7 KB gzipped: the screen and done state (~3 KB), the timer model, selection and prefs (~1.5 KB), the settings card (~1.5 KB), the break watcher and the tone (~1 KB). The six catalogs grow by about forty messages each. Binary: the `Schema` entries only, a few hundred bytes. Container image, runtime memory and the server's work per request unchanged; the server never sees the timer.

## Interface budget

- Rows of chrome above the first item: the header only (1 of 2); the timer card is content.
- Task properties visible by default: title, project, due, notes, subtasks (5 of 7).
- Primary sidebar destinations: unchanged (none added).
- Vertical scroll regions: the content column only (1 of 3).
- Shortcuts: `go.focus` (global) and five `view` entries for `focus`, registered in `web/src/lib/shortcuts.ts`, no conflict (`VIEW_SCOPES.focus = []`).

## Risks / Trade-offs

- [Background tabs are throttled, so the end of a session is noticed late while hidden] → the interval is a display aid only; the end is computed from the clock on the next tick, on `visibilitychange` and on `focus`, and the hidden-tab notification is at worst a minute late in browsers that throttle timers to once a minute; the done state is always right when the tab returns.
- [Two tabs both reach the end in the same second] → the transition runs in a Dexie transaction that re-reads the row and gives up if another tab already wrote `done`; the notification tag collapses duplicates; the entry stop converges per field.
- [`time-tracking` lands with a different function surface than D4 assumes] → the seam is one adapter file; only it changes. If `time-tracking` is not merged first, the build ships `noopLogger` and the "Degraded without time tracking" scenario is the behaviour.
- [The task is completed or trashed elsewhere mid-session] → the screen watches the task row; a `completed_at` or `deleted_at` ends the session (`complete` transition, entry stopped) and offers the next task.
- [Audio autoplay policies block the tone] → the context is created on the Start click; if `AudioContext` is unavailable or `resume()` rejects, the tone is skipped silently and the done state still shows.
- [A long Flowtime session spans midnight and the focus list changes] → the current task is pinned by id in the row; "Next task" reads the list as it is now.
- [`n` and `b` are letters a user may type by habit while the notes are focused] → the dispatcher never fires view keys in a typing target, and the notes are read-only on this screen (D6).
- [Five new `view` entries add a section to the cheat sheet] → the section lists five rows and appears only while the Focus view is on screen, like the triage section.

## Migration Plan

Ships with the web bundle and a server release that knows the eight schema fields. Order: `time-tracking` first (or the seam falls back), then this change. The Dexie upgrade to version 21 adds one table and runs on first load; an older client receiving the new `user_prefs` fields stores and forwards them unchanged (`offline-first-sync` "Op schema contract"). Rollback: revert the commit; the `focus` table is harmless when unused and the preference fields are ignored by a client that does not know them.

## Open Questions

- Whether the Flowtime break should be proportional to the time worked (a fifth, rounded to five minutes) rather than the short break length. The spec only requires a break after a Flowtime session when the user takes one, and D10 uses the short break length; the model's `finish` takes the break length as an argument, so this can change without touching the screen or the tasks.

## Implementation notes

- **Time tracking is bound, the seam stays thin (D4).** `time-tracking` landed first, so `web/src/lib/focus/index.ts` binds `focusLogger()` to `timeTrackingLogger` (`startTracking(taskId, { now })` to start; stopping ends only the session's own entry through `updateTimeEntry(id, { ended_at })`, so a `y` entry on another task is never stopped by Focus). Time tracking has no paused entry ("a pause is a stop, resuming starts a new entry"), so the interface is `start`/`stop`/`running` instead of `start`/`pause`/`resume`/`stop`/`running`: pausing ends the entry, resuming starts a new one. The focus-mode delta spec's "Sessions are time entries" requirement and its "Pause is not work" scenario now say this. `noopLogger` is kept because the spec keeps "Degraded without time tracking" (reworded to "when time cannot be logged"); it is reachable through `setFocusLogger` (tests), and a logger that throws (for example not signed in) is caught, so the timer keeps working and writes nothing.
- **Dexie v21 (D2).** Dexie was at v20 (time-tracking), so the device-local `focus` table is version 21, as the change's proposal, design and tasks now say.
- **Shortcuts re-checked (D7).** Against `web/src/lib/shortcuts.ts` as it is now, `g Shift+F` is free (`g Shift+P` is All projects, `Shift+F` alone is `project.fields` in the project view). Space, Enter, `b`, `n` and Esc are `view` entries of `focus` with `VIEW_SCOPES.focus = []`, so they never meet `list.tick`, `list.open`, `list.blocked-by`, `list.park` or `panel.escape`. The one new override is on `vim.leave-field`, which now lists `focus.escape` beside `triage.escape`. The cheat sheet shows the Focus section first on the Focus screen (`contextSections`).
- **Today is the logical today.** The focus list is `storedFocus(review, useToday())`, so with a day start of 04:00 the list chosen at 00:30 still applies until 04:00.
- **Where the code lives.** Pure model `lib/focus/timer.ts`, preferences `lib/focus/prefs.ts`, local row `lib/focus/state.ts`, session actions (row transition plus logger) `lib/focus/session.ts`, selection `lib/focus/select.ts` (`nextFocusTask` and `focusTarget`, the address/session/list rule as one tested function), tone `lib/focus/tone.ts`, live entry read `lib/focus/live.ts`. The engine (`app/focus/useFocusTimer.ts`: end transition, tone, notification, "completed elsewhere", "entry stopped elsewhere") is mounted once by the shell through `BreakReminder`, so a session ends on time on every screen, not only on the Focus screen; the Focus screen itself only displays and acts. The settings card is `app/focus/FocusSettings.tsx`, re-exported from `PreferencesPanels.tsx`.
- **Settings Help (6.1, settings-navigation "Focus settings").** Settings cards may not carry a help link (`settingsAnatomy.test.tsx`, one `data-help-screen` per section page). The card's last row, "How Focus works", has a button "Open the focus guide" that opens Help on the `settings/focus` screen (`docs/focus.md`), which keeps the rule and meets the scenario.
- **Header (D6).** Help is an item of the overflow menu (the spec's menu lists it) instead of the page header's Help icon, so the header shows two actions and the menu. The header's Back action is Esc's visible button (focus-mode "Session controls": every key is also a visible button); it returns to the view shown before Focus (`routeBeforeFocus()` in the router).
- **Done state and Space.** In the done state the header's button reads Start and starts a new work session; the done state's first action (Start the break, Start the next session, ...) takes the focus, so Space or Enter there runs it.
- **Completion.** Enter and Complete use `completeWithUndo` (recurrence and the Undo toast, as Process the Inbox does). The list's "complete parent too?" offer belongs to a list's selection and is not shown on this screen, which has no list.
- **Completing moves on.** After a completion the done state names the completed task and the screen already shows the next open task of today's focus (the address follows with `replace`); when none is left the done state says "Today's focus is done." and offers the picker.
- **Docs.** `docs/focus.md` lists the live specs `web-app` and `settings-navigation`: `docs-check` refuses a spec name that is not in `openspec/specs/` yet; `focus-mode` is added at archive time. The screenshot pair was captured with `node scripts/docs-screenshots.mjs focus` against the demo data (the picked task varies, so the alt text does not name it).
- **Bundle.** Measured with `npm run build`: the lazy Focus chunk is 4.5 KB gzipped and the main bundle grows by about 5.7 KB gzipped (the engine, model, session actions, settings card and break reminder are in the shell), about 10 KB in all instead of the 7 KB estimated. No dependency and no asset (no audio file in `web/dist`).
- **Not done here.** Visual baselines (`make ui-baselines`) need Docker; the three stories were built and rendered in the bundled Chromium (no horizontal scroll at 375 px) and pass the a11y gate in both themes. The browser smoke test of 8.1 was replaced by the Shell-level tests and the screenshot run against a real server.
