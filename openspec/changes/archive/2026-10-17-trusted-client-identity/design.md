# Design: trusted client identity

## D1 Who is a trusted proxy
`clientIP` first looks at the connection's peer. If it is not trusted, it is the client and every forwarded header is ignored. If it is, the peer is appended to the `X-Forwarded-For` hops and the client is the nearest untrusted hop from the right; a Cloudflare edge hop with `CF-Connecting-IP` yields that address, and an all-trusted chain yields its first hop. `fromTrustedProxy` (forwarded host and scheme) uses the same set. The default set is `config.PrivateRanges` (loopback, RFC 1918, ULA, link-local, matching what `internal/outbound` treats as private). A configured list replaces it. `cloudflare` keeps the default because Cloudflare traffic nearly always arrives through a local proxy or tunnel, so the documented `OPENTODO_TRUSTED_PROXIES=cloudflare` keeps working. `private` names the default for lists that add a public proxy. A list with no address overlapping the default gets a configuration warning (owner notice and one log line), because the local proxy would otherwise silently become everyone's address. Invalid entries still never widen trust; all-invalid equals unset.

## D2 Limiter keys and sweeping
`rateLimiter` normalises keys with `addrKey`: an IPv6 address becomes its /64, IPv4 and mapped addresses their dotted form, other keys (user ids, hashes) are unchanged. Compound keys (`feed:`) are normalised by the caller. Sweeping moved out of `hit`: every limiter registers a weak pointer with one package sweeper goroutine, which sweeps live limiters once a minute and drops collected ones, so servers built in tests or per tenant do not leak. `check` (blocked plus one "first refusal" per window) lets sign-in count failures only and still log one `rate_limited` audit event per window.

## D3 Per-account failures
`accountLimiter` (10 per 15 minutes) is keyed `user:<id>`; a sign-in for an address without an account uses `email:<normalised>`, so the answer does not reveal whether the account exists. It is checked before the password, the code (the challenge's user is read with `MFAChallengeUser` without spending an attempt) or the re-authentication is verified, so a locked account cannot be probed. Failures are counted where the existing code already records them; any new session for the account (`issueSession`) and a successful re-authentication clear it. Lockout is 429 `account_locked` with `Retry-After` until the window ends. Accepted risk: an attacker who knows an email address can keep its password sign-in locked; other sign-in methods and existing sessions are unaffected.

## D4 Setup code
`auth.Service` holds the code in memory (`setupcode.go`). `httpapi.New` calls `PrepareSetupCode` after options; it generates 10 random bytes (16 base32 characters, shown as four groups of four) only when no setup token is configured and no account exists, and the server logs it once at WARN with a plain sentence and a `setup_code` attribute. `RegisterFrom` takes `local` (the resolved client address is loopback/private/link-local): a configured token is required from every address as before; otherwise a non-local first registration must match the code (SHA-256 then constant-time compare, case and dashes ignored). The code is discarded after the owner's transaction commits; with no code (already discarded, or never generated) a non-local first registration is refused. `RegisterWithSetupToken` keeps its behaviour (`local=true`) for other callers.

## D5 Origin and transport
With a base URL, `originAllowed` still accepts `Origin` equal to the base origin; the `Origin == Host` fallback now also requires `Host` to be the base URL's host. `secureCookie(r)` is `SecureCookies() || requestIsHTTPS(r)` for every cookie set or cleared. `securityHeaders` adds HSTS for an https base URL only, so a LAN install over http never pins https.

## Data model, size, interface
No migration, no op or schema change, no dependency (`weak` is the standard library). Memory: one goroutine and one weak pointer per limiter. The web change reuses the existing setup-token field (label and help text switch), so the interface budget is unchanged; four new messages in five catalogs.
