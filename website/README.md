# OpenTodo website

The public landing page for OpenTodo. Plain HTML, CSS and JavaScript: no build step, no dependencies.

The app's rules (no telemetry, no third-party requests) apply to the app only. The website may load web fonts, call the GitHub API for the star count, and use analytics (self-hosted Umami, loaded in the `<head>` of `index.html`).

## Run locally

```bash
cd website
python3 -m http.server 4173   # or any static server
```

Open http://localhost:4173.

## Deploy on Coolify

Add a second resource to the project:

1. **+ New Resource → Public Repository**, `https://github.com/pixari/opentodo`, branch `main`.
2. **Build pack**: Dockerfile. **Base directory**: `/website`. **Port**: `80`.
3. Assign the domain and deploy.

Any static host works too: publish the contents of this folder as-is. Docs pages live at `/docs/<page>/index.html`; the host must serve `index.html` for a directory URL (nginx: `try_files $uri $uri/index.html`).

## Files

| Path | What |
| --- | --- |
| `index.html` | All page content |
| `styles.css` | Styles, dark theme, responsive layout |
| `main.js` | Hero demo app, keyboard shortcuts, sync playground, install tabs, feature tour |
| `assets/` | Logo, icons, social image `og.png` |
| `assets/shots/` | App screenshots as WebP, generated by `scripts/screenshots.mjs` |
| `docs/` | The documentation site, **generated** from `../docs/` by `make docs` and committed (never edit it by hand): one folder per page, `search.json`, `docs.css`, `docs.js`, `images/`. Sources of the stylesheet and script are in `web/scripts/docs/assets/`. |

## Refresh the screenshots

Every screenshot on the page is a real capture of the app, taken by `scripts/screenshots.mjs` against a fresh server. The script creates three accounts (Ada the owner, Bob and Chen as members), seeds shared projects, sections, subtasks, labels, recurring tasks, comments with @mentions, reminders, saved views, a dashboard, trash, webhooks, an app password, tokens and a backup, then captures each view. It pins the browser clock to 08:40 UTC on the next Tuesday, Wednesday or Thursday so every run looks the same, and encodes WebP with Chromium itself (no image tools needed).

```bash
make web && go build -o bin/opentodo ./cmd/opentodo
# Fresh data directory. The OPENTODO_EMAIL_* values only make the "Email to task"
# panel show an address; nothing listens on 127.0.0.1:1, the poll just fails.
OPENTODO_ADDR=:18767 OPENTODO_DATA_DIR=$(mktemp -d) \
OPENTODO_EMAIL_ADDRESS=todo@example.com OPENTODO_EMAIL_IMAP_HOST=127.0.0.1:1 \
OPENTODO_EMAIL_IMAP_USER=todo OPENTODO_EMAIL_IMAP_PASSWORD=demo ./bin/opentodo &

npm i -g playwright@1.56.1 && npx playwright install chromium   # once; any recent Playwright works
OPENTODO_URL=http://127.0.0.1:18767 node scripts/screenshots.mjs   # from the repository root
```

Output:

- `website/assets/shots/*.webp`: every shot (desktop 1440×900 at 1.5×, so 2160×1350; phones 390×844 at 2×). About 30 files, 2.6 MB in total; keep the folder under 3 MB.
- `docs/screenshots/{today,project,day,mobile-dark}.png`: the four PNGs `README.md` embeds.

Arguments: `node scripts/screenshots.mjs [png-dir] [webp-dir]`. `ONLY=today,board` captures a subset (seeding always runs); `CHROMIUM_PATH` points at a browser binary. The script needs an **empty** data directory because it creates the owner account; restart the server with a new directory for each run. Use a fresh browser profile: the app's service worker can otherwise serve an older bundle.

The feature tour (`#tour`) has chapters (`data-chapter`) whose panels (`data-panel-for`) hold one button per feature; each button names its image in `data-shot` and its alt text in `data-alt`. To add a feature, capture a new shot in `scripts/screenshots.mjs`, then add a button to the right panel. `index.html` gives the tour image `width="2160" height="1350"`; keep new desktop shots at that size.

The specs section links each shipped feature to its live spec under `openspec/specs/<capability>` on GitHub, or to its archived change under `openspec/changes/archive/<date>-<name>/` when the change only touched a broad spec.

Live at https://opentodo.pixari.dev. The canonical, `og:url` and `og:image` URLs in `index.html` are absolute; update them if the domain changes.
