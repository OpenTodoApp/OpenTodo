# Work on the native app

`mobile/app/` is the phone app in progress (OpenSpec change `native-app-foundation`): React Native with Expo, drawn with the system's own views, and sharing sync, ops, encryption, dates, recurrence and quick add with the web app. It is not the iPhone or Android shell in `mobile/ios` and `mobile/android`, which load the web app.

## Without a Mac

Most of the work needs only Linux and Node 24:

```sh
make app              # npm ci in mobile/app, type-check, lint, the Jest tests, the shared module list
cd mobile/app && npx jest test/recurrence.test.ts
cd mobile/app && npx expo export --platform ios   # bundles the JavaScript as the app would
```

`make app` installs the app's own dependencies and never web's; `make check` leaves it out unless you run `make check APP=1`. The iOS and Android builds run in CI, on a pull request that changes `mobile/app/`, so you do not need Xcode or the Android SDK. With an Android SDK, `npx expo prebuild --platform android` and `./gradlew :app:assembleDebug` in `mobile/app/android` build it locally.

The native projects (`ios/`, `android/`) are generated by `npx expo prebuild` from `app.config.ts` and are never committed. Change the app's native setup there, or in a config plugin.

## The shared library

The app imports `web/src/lib` as `@shared/*`, through Metro (`metro.config.js`), Jest (`jest.config.js`) and TypeScript (`tsconfig.json`). Every package a shared module names comes from `mobile/app/node_modules`, so there is one React and the app needs nothing installed in `web/`.

- **What the app may import.** Only `@shared/*`. ESLint refuses `web/src/app`, `web/src/ui` and the browser-only packages (`react-dom`, `dexie-react-hooks`, `prosemirror-*`, `maplibre-gl`).
- **The host.** A shared module never reads `window`, `document`, `navigator`, `localStorage`, `BroadcastChannel` or `indexedDB` directly; it asks `web/src/lib/platform.ts`. The app installs its implementation (`src/platform.ts`, `src/host.ts`) at start-up. `make repo-check` fails on a browser global in a module listed in `mobile/app/shared-modules.json`.
- **The list.** `node mobile/app/scripts/shared-modules.mjs` prints the modules the app shares: the import graph (`scripts/shared-graph.mjs`) of the sync path and of every `@shared/*` module the app's code and tests import. `--write` rewrites `shared-modules.json`, and `make app` fails when the file is stale.
- **Vite forms.** `import.meta.glob` and `import.meta.env.MODE` are compiled by `babel/vite-import-meta.js`, so the shared i18n layer loads the same catalogs as the web app.
- **Vectors.** The tests in `mobile/app/test/` run the shared vectors (hybrid clock, recurrence, quick add, project flows, encryption) on the app's runtime against the same modules the web app runs. A change that breaks one fails in both.

## Dependencies

Every package is pinned exactly and has a line in `mobile/app/DEPENDENCIES.md` saying why; `make repo-check` fails otherwise. `mobile/app/.npmrc` installs only releases at least 14 days old. Dependabot proposes the app's updates once a week in one pull request.

## CI lanes

| Job | Runs when | What |
| --- | --- | --- |
| `app-check` (Linux) | `mobile/app/`, a module in `shared-modules.json`, `web/src/generated/opSchema.ts`, `web/src/locales/`, the `Makefile` or the workflow changes | `make app` |
| `App builds / App on iOS` (macOS) | a change under `mobile/app/`, release tags, nightly | `expo prebuild`, a Release simulator build without signing |
| `App builds / App on Android` (Linux) | the same | `expo prebuild`, a debug build, the unit tests |

A web-only pull request runs none of them, and a change to a shared module runs only `app-check`. The cases are in the path filter's test, `scripts/repo-checks.test.mjs`.
