# Easypanel template

An [Easypanel](https://easypanel.io) template in the format of [`easypanel-io/templates`](https://github.com/easypanel-io/templates):

| File | What it is |
| --- | --- |
| [`meta.yaml`](meta.yaml) | The listing (description, instructions, links, benefits, features, tags) and the form: service name (`opentodo`) and image (`ghcr.io/pixari/opentodo:0.9.0`) |
| [`index.ts`](index.ts) | `generate()`: one app service from that image, the domain `$(EASYPANEL_DOMAIN)` on port 8080, the volume `data` on `/data`, and `OPENTODO_BASE_URL=https://$(PRIMARY_DOMAIN)`, a generated 32-character `OPENTODO_SETUP_TOKEN`, `OPENTODO_ALLOW_SIGNUP=false` and an empty `OPENTODO_TRUSTED_PROXIES` |
| `assets/logo.svg` | The logo mark, identical to [`../coolify/opentodo.svg`](../coolify/opentodo.svg) |
| `assets/screenshot.png` | [`docs/images/board-light.webp`](../../docs/images/board-light.webp) as PNG |

The image is pinned to a release, not `stable`: the repository's checklist asks for "static versions" and "specific versions (2.1.7, instead of 2.1, or 2)". `make check` (`scripts/deploy/easypanel.mjs`) fails when the default image is not the latest release in `CHANGELOG.md`, and on the shared rules in [`../deploy.json`](../deploy.json). It reads the image from `meta.yaml` and the environment, port and mount from `index.ts`.

**Status: not yet submitted.**

## Install it now, without the template list

Create an **App** service in an Easypanel project and set it up by hand as [docs/self-hosting/easypanel.md](../../docs/self-hosting/easypanel.md) describes (image, environment, domain on port 8080, volume on `/data`).

## `upstream/`

[`upstream/templates/opentodo/`](upstream/templates/opentodo/) is the folder at its path in `easypanel-io/templates`, identical to the files here (`make check` fails when they drift). Edit the files here, then copy:

```bash
cp deploy/easypanel/meta.yaml deploy/easypanel/index.ts deploy/easypanel/upstream/templates/opentodo/
cp deploy/easypanel/assets/* deploy/easypanel/upstream/templates/opentodo/assets/
```

`meta.ts` and `templates/index.ts` are generated by their build and ignored by their git, so they are not kept here.

## Submitting to easypanel-io/templates (maintainer)

Needs a GitHub account and Node.js.

1. Fork [`easypanel-io/templates`](https://github.com/easypanel-io/templates), clone the fork and copy the template in:

   ```bash
   git clone https://github.com/<you>/templates && cd templates && git checkout -b opentodo
   cp -R /path/to/opentodo/deploy/easypanel/upstream/templates/opentodo templates/opentodo
   npm ci
   npx prettier --check templates/opentodo
   npm run build
   ```

   `npm run build` generates `meta.ts` from `meta.yaml` and type-checks `index.ts` against Easypanel's types.
2. Test it in the playground (`npm run dev`, open the OpenTodo template, check the generated JSON) and, if you have an Easypanel instance, create a project from that JSON: open the domain, create the owner with the setup token from the service's **Environment** tab, add a task, redeploy and check it is still there.
3. Commit only `templates/opentodo/` and open the pull request with the title and body in [`upstream/PR.md`](upstream/PR.md).
4. Answer review comments here first, then copy to the fork.

## After a release

The template names one version, so it needs a change after each release: set `appServiceImage`'s default in `meta.yaml` to the new version, add a `changeLog` entry, copy both to `upstream/` (`make check` fails until the image follows `CHANGELOG.md`), and open a pull request to `easypanel-io/templates` with that change. Existing Easypanel services keep their image until the user changes the image in the service's source settings and redeploys.
