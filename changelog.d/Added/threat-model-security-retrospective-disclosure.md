- **A threat model, a security retrospective and a disclosure policy with response times.** [docs/security/](docs/security/README.md) now publishes the [threat model](docs/security/threat-model.md): the assets, the trust boundaries and thirteen attacker profiles, from an anonymous visitor to a malicious server for an encrypted account, a prompt-injected AI agent and another tenant in host mode. For each it says what is defended, by which mechanism, which tests would fail if that broke, and what is not defended. [Security limits](docs/security/limits.md) says in one place what is not protected: what the operator sees with and without end-to-end encryption, what is unencrypted at rest, what backups contain, and how far host mode and the demo isolate. [How we verify security](docs/security/how-we-verify.md) is the retrospective people asked for: the op-log sync and its convergence tests, the encryption format and the vectors shared by the app, the server and `ot`, the route policy test, token scopes, the SSRF policy, importer limits, upgrade tests, static analysis and fuzzing, every past security fix and the gaps still open. [SECURITY.md](SECURITY.md) now promises an acknowledgement within 3 business days and an assessment within 10, fix targets per severity (7 days for Critical, 30 for High, 90 for Medium, the next minor for Low), coordinated disclosure within 90 days with an advisory and a CVE, a safe harbour for research on your own instance, and which versions get fixes after 1.0; a repository check keeps those numbers from disappearing. Every server now answers `/.well-known/security.txt` (RFC 9116) with the same reporting channels and a link to the policy; a comment in it says that problems with how a particular server is run belong to its operator. The [scope for an independent review](docs/security/review-scope.md) is ready: no external review has taken place yet, and none is claimed. From 1.0, `make release-prepare` refuses a release whose review findings break the fix rule, once a review exists. (OpenSpec `external-security-review`, #588)
